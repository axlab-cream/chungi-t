# 커플 시그널 저장 리포트 — 목차별 이미지와 공용 리더

## 문제

`couple_signal`은 실제 저장 리포트가 21개 해석을 갖지만 `summary-only` 설정과 공용 리더의 하드코딩 키 때문에 토글 이미지를 전혀 표시하지 못했다. 상세 페이지 자체의 2열·단일 항목 탐색 레이아웃도 저장 리포트 전체를 읽는 공용 리더와 충돌했다.

## 결정

- 저장 원문과 회원별 계산값은 변경하지 않는다.
- `sectionImages`를 실제 서비스 목차 순서와 1:1로 연결한다.
- 이미지 한 장에는 장면 하나만 담고, 3:2 가로형 WebP로 최적화한다.
- 시맨틱 읽기 표, 오행 계산 표, 실제 분석이 있을 때만 나오는 대운 그래프는 공용 렌더러를 재사용한다.
- 임의 점수·가짜 그래프·관계 사실 단정은 추가하지 않는다.
- 저장 리포트가 채워진 뒤에만 구형 context/list와 이전·다음 탐색을 숨긴다.

## 구현

- `longform-blocks.json`: `summary-only` 제거, `summaryImageFit: wide`, 21개 고유 이미지 연결.
- `umsh-report-access.js`: `couple_signal`을 대표 이미지 전용 키에서 제거.
- 서비스 상세 HTML: 448px 공용 폭, 15px/1.9 본문, 16px/1.65 결론, 펼치기/접기 상태, 전체 문서 스크롤, 3:2 이미지 적용.
- 회귀 테스트: 이미지 개수·고유성·파일 존재·공용 리더 상태·구형 UI 조건부 제거를 고정.

## 재사용 교훈

목차별 이미지를 도입할 때는 설정 파일만 바꾸면 부족하다. 공용 렌더러의 동기 하드코딩 가드, 서비스 HTML의 구형 레이아웃, 이미지 순서 계약을 함께 확인해야 한다. 운영 원문이 인증으로 보호되면 원문을 추측하지 말고 정적 목차 계약과 공용 렌더러 검증으로 범위를 제한한다.
