# 저장 해석의 분량을 지키는 편집 시안 적용

## observation

- 긴 해석을 짧은 요약으로 바꾸고 원문을 접으면 본문이 사라진 것으로 받아들여진다.
- 첫 상세 카드는 약 850토큰(`o200k_base`)이지만 다른 카드의 원문은 약 320~560토큰으로 편차가 컸다. 토큰은 모델 토크나이저마다 다르다.
- 독자가 원하는 것은 짧은 요약으로 대체된 리포트가 아니라, 원문 전체를 보면서 쉬운 설명과 시각적 근거를 함께 검토하는 화면이다.

## decision

- 운영 원문은 기본 펼침 본문에 전문 그대로 둔다. 쉬운 제목·선행 결론·생활 장면·확인 행동은 추가 레이어로 붙인다.
- 카드별 분량이 부족할 때는 같은 문장을 반복하지 않고 구체적 장면, 반대 경우, 확인 질문, 한계를 보강한다.
- 일부 값만 있는 계산은 숫자 카드로만 표시한다. 전체 분모 없는 비율 차트, 운세 점수, 날짜 예측은 만들지 않는다.
- 사용자의 검토 후 PDF 저장·브라우저 인쇄 동작은 이 디자인 검토본에서 제거했다.

## verification

- 로컬 격리 검토본의 상세 카드 16개에 원문의 답·근거·행동이 그대로 남아 있다.
- 카드별 쉬운 제목, 실사 이미지, 표·단계·확인 목록, 가독성 강조를 확인했다.
- 집중 테스트 6/6, JavaScript 구문 검사, TypeScript 검사, 로컬 브라우저의 가로 넘침 없음 확인.
- 운영 데이터와 서비스 파일은 변경하지 않았다. 고객 이름·리포트 ID·원문 전문은 이 KMS 기록에 넣지 않았다.

## lesson

- 편집 시안은 원문 보존 여부를 먼저 합의해야 한다. 특히 긴 유료 해석은 길이 자체도 사용자가 검토할 품질 요소다.
