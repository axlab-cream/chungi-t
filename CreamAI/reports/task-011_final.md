# 인사이트

**판단이 필요해 보이는 것도 먼저 코드에 근거가 있는지 찾아본다.**
"UMSH를 뗄지"는 취향 문제처럼 보였지만 구조화 데이터가 이미 `운명상회` 를 선언하고 있었다.
결정할 것은 브랜드가 아니라 **선언과 제목의 불일치를 어느 쪽으로 맞출지**였다.

**"차단됐다"를 코드 리뷰로 판단하지 않는다. 요청을 보내서 판단한다.**
적대적 매트릭스가 내 가드의 구멍 두 개를 찾았다 — `req.path` 는 디코딩되지 않고,
`send` 는 경로 끝의 슬래시·점을 무시한다. 특히 `PROMPT.md/` 는 **원문 4017바이트를
그대로 반환**하고 있었다. 테스트를 통과시키려고 만든 케이스가 실제 취약점을 찾았다.

**확장자 목록은 형식을 세는 방식이라 새 형식에 진다.** 스크래핑 결과가 `.html` 로
저장돼 있어서 목록을 지나갔다(Codex Critical). 그 폴더가 만드는 **URL 공간을 닫는** 편이
확실했다. 다만 그것도 임시 방편이고 구조 전환(U31)이 답이다.

**문자열을 조립해서 파일을 만들지 않는다.** 이 Task 에서 두 번 데었다.
파이썬 슬라이싱으로 `about.html`·`portal.html` 527줄을 지웠고(즉시 복원),
정규식 편집 과정에서 백스페이스 제어문자(0x08)가 박혀 `<script\b` 가 죽은 패턴이 됐다.
→ 유일 매칭을 확인한 **문자열 치환만** 쓰고, 편집 직후 `git diff --stat` 으로 줄 수를 본다.
특수문자를 다뤘으면 `cat -A` 로 실물을 확인한다.
