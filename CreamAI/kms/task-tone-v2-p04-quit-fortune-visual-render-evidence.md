# KMS note — Quit Fortune actual-result visual acceptance

- Reuse one immutable complete isolated result through the production saved-result reader; do not replace it with a sample component or generated fixture copy.
- Validate identity, service, completion and exact section count before serving, and keep the QA process loopback-only and read-only.
- For long disclosure reports, open every section at desktop and exact mobile width, then verify nonempty bodies, paragraph ranges, overflow, target size and keyboard toggle.
- A fixed control outside the centered content column is acceptable only when it remains in the viewport, does not obscure content and is excluded from print.
- Print acceptance requires structural checks for all titles and answers plus visual review of representative first, middle and final pages.
- Store screenshots and PDFs only in ignored local cache. Track sanitized hashes, counts and findings; never copy provider prose or personal data into release evidence.
