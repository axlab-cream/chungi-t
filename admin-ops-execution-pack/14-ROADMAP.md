# 로드맵
일정은 팀·코드 상태 확인 전의 추정이다. 2명 개발+파트타임 운영 검수 기준 8~12주 범위로 계획하되, 외부 PG·정책·실제 저장소 차이에 따라 재산정한다. 완료 판정은 날짜가 아닌 게이트다.

| 단계 | 예상 구간 | 작업 | 사용자에게 제공되는 결과 | 종료 게이트 |
|---|---|---|---|---|
| M0 발견·기준 | 1주 | T01~T04 | 현황·스키마·서비스·회귀 기준 | 코드·WIKI 차이 해결 |
| M1 조회 운영 | 2~3주 | T05~T13 | 직원 로그인·주문·회원·리포트·CS | 권한·마스킹·실API |
| M2 거래·복구 | 4~5주 | T14~T21 | 환불·대사·실패복구·로그 | 중복·불확정·권한 회귀 |
| M3 편집·지식 | 6~8주 | T22~T30 | CMS·미디어·코퍼스·평가·발행 | 버전고정·평가·롤백 |
| M4 분석·개인정보 | 9~10주 | T31~T35 | 퍼널·비용·내보내기·요청처리 | 원장 대조·데이터 정책 |
| M5 통합 안정화 | 11~12주 | T36~T38 | 출시 후보·운영 런북 | 종합 인수·복구 실습 |

작업량이 작으면 겹쳐 진행할 수 있지만 의존성을 생략하지 않는다. 예: T22~T28은 M2 일부와 병행 가능하며 release 활성화는 T29 조건을 지켜야 한다.

## 출시 묶음
MVP-A: M0+M1. 내부 조회용 출시; 금융 변경·발행 버튼 비활성.
MVP-B: M2. 거래 쓰기 플래그 분리; 모의 PG 검증 후 운영 권한에 따라 활성화.
V1: M3+M4+M5. 종합 관리 출시.
전체 요구가 M1만으로 완료되었다고 보고하지 않는다.

## 의존성 병목
PG 취소 계약 미확인: 요청·승인·모의 adapter·UI·대사 도구까지 진행, 실환불은 blocked.
운영 DB 권한 없음: 합성 DB migration·회귀·조회 adapter 진행, 실연결 검증만 blocked.
정책 미확정: 보존·삭제 설정 화면·dry-run까지 진행, 삭제 실행은 disabled.
runtime release 전략 미선택: 파일 bundle 전략을 기본으로 준비하고 ADR-04에서 확정.

## 우선순위
P0는 접근·금전·결과보존·진단 안정성. P1은 종합 운영 완성 기능. P2 확장은 구독, 쿠폰, 개인화 추천 실험, 외부 CRM 양방향 연결로 현재 작업목록에 넣지 않는다.
