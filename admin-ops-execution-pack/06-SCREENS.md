# 화면별 상세 명세
모든 표의 금액은 KRW 정수이며 UI에서 원 단위를 붙인다. 주문시각·승인시각·환불시각을 혼동하지 않는다.

## S01 운영 홈 /admin
필터: 기간(오늘/7일/30일/직접), 서비스, 환경. KPI: 승인액, 환불액, 순거래액, 승인건수, 제공 지연, 생성 실패, 미처리 문의. 각 값에 기준시각·집계원·분모·전기 비교를 표시한다. 하단은 '결제 후 미제공', 'PG 불확정', '품질 검수 대기', '발행 예정' 우선순위 큐. 특정 서비스 장애는 전체 합계에 묻히지 않게 별도 표시. 집계 지연은 마지막 성공시각과 함께 표시하고 데이터 조회 실패는 0으로 대체하지 않는다.

## S02 서비스 목록·상세
목록 열: 이름, canonicalKey, 무료/유료, 카테고리, discovery 상태, 판매 가능 여부, 기준 가격, 발행 버전, 품질 상태, 수정시각.
상세 탭: 개요 / 카드·랜딩 / 입력·미리보기 / 상품·가격 / 미디어 / 프롬프트·코퍼스 연결 / 분석 / 이력.
필드: title, tagline, summary, category, order, posterAssetId, videoAssetId, alt, landingPath, availability, discoveryVisibility, effectiveAt, revision.
검증: key 변경 금지, 내부 route allowlist, 음수·소수 원화 금지, paid 상품 0원 금지, 필수 미디어 검사, 발행 전 링크 확인.
가격 변경은 신규 주문만 적용한다. 공개 숨김은 기존 고객 결과·구매권한을 해제하지 않는다. 판매 중단은 서버의 신규 주문 생성에서도 검사한다. 캐시된 옛 가격은 주문시 현재 가격을 다시 확인시킨다.

## S03 콘텐츠·미디어
콘텐츠 유형: 서비스 카드, 랜딩 문구, FAQ, 공지, 배너, 약관 링크. 제목, 본문, 노출 위치, 대상 서비스, 예약 시각, 상태, revision, 검수 의견.
원문 HTML 임의 삽입을 기본 허용하지 않고 구조화 필드로 시작한다. HTML이 필요하면 허용 요소 기반 정제 후 미리보기.
미디어: 파일명, MIME 실검사, 크기, 가로·세로, 길이, poster, alt, 저작·사용 근거, checksum, 사용처, 버전.
업로드 중/실패/검사 중/승인/미사용을 구분한다. 참조 중인 자산 삭제는 차단한다. 이미지 10MB·영상 100MB를 초기 제품 제한안으로 두고 실제 저장소 제한 확인 후 조정한다. 영상 poster 누락·깨진 자산·모바일 비율을 발행 검사에 포함한다.

## S04 주문 상세
헤더: orderId, 마스킹 회원, productKey, 주문 금액, 주문 상태, PG 확인 상태, 제공 상태, 결제 환경.
타임라인: 주문 생성 → 승인 요청 → PG 결과 → 권한 부여 → 리포트 생성/열람 → 환불 요청/결과.
세부: tid(재무 제한), 승인코드(재무 제한), PG 확인시각, reportId, 중복 의심, 환불 누적, 대사 차이.
CTA: PG 상태 재조회, 문의 연결, 환불 요청. 'paid로 변경' 같은 직접 상태 편집은 제공하지 않는다.
미연결 reportId는 정상 구형 주문일 수도 있으므로 소유자·상품 대조 후 복구 후보로 처리한다.

## S05 환불·대사
환불 폼: orderId, 범위(전액 기본), 요청 금액, 사유 코드, 설명, 관련 문의, 주문 revision. 최대 환불 가능액은 서버 계산.
승인 화면: 요청자·승인자 분리, 이전 환불·열람 여부·PG 근거. 실패/timeout은 불확정 상태를 표시하고 재조회부터 제공한다.
대사 표: PG 승인액·환불액, 내부 승인액·환불액, 차이, 수집원, 기준일, 최종 확인시각, 담당자.
CSV를 대사 소스로 쓸 경우 파일 checksum·행 오류·중복 import를 표시한다. PG API 지원을 확인하기 전 자동 대사 완료라고 표시하지 않는다.

## S06 회원·문의
검색은 내부 ID·주문 ID 우선, 이메일은 권한 있는 정확 일치 검색. 목록: 마스킹 이름/메일, 가입·최근 활동(실제 기록 있을 때), 주문수, 열린 문의.
상세 프로필 원문은 기본 숨김. 별도 권한과 사유를 입력한 단기 reveal 동작으로 조회하고 감사 기록.
문의: 종류(결제/생성/해석/접근/개인정보/기타), 우선순위, 상태, 담당자, 연결 주문·리포트, 내부 메모, 해결 코드.
고객 연락 자동 전송은 별도 채널 연결 전 구현 완료로 간주하지 않는다. 초기에 내부 처리·답변 초안까지만 제공 가능.
탈퇴 요청은 본인확인·범위·보존 예외 검토·익명화/삭제 작업·결과 검증 타임라인을 표시한다.

## S07 리포트·생성 작업
목록: reportId, 서비스, 마스킹 소유자, 결제 접근 상태, 완료/전체 항목, 상태, 생성 시작·완료, 최종 오류, 버전.
상세 항목: sectionId, generationId, attemptId, 모델, 사용량(기록될 때), 지연, 품질 오류 코드, corpus fingerprint, prompt version.
원문 프롬프트·입력·생성물은 별도 제한 열람이다. 로그 탭에는 메타데이터만 표시한다.
재시도는 실패/만료된 항목만, 비용 예상과 사유를 제시한다. 동시 클릭은 단일 작업을 반환한다. 완료 결과는 새로 생성하지 않는다. 전체 재생성은 신규 보고서 ID의 별도 개발 범위로 둔다.

## S08 코퍼스·프롬프트·평가
3열 편집: 목록 / 블록 필드 / 검증·출처·사용 서비스. 버전 diff는 삭제·추가·필드 변경을 구분.
검색 테스트: 합성 질문+Feature JSON → 후보 블록 ID·점수·적용 조건 → 사용/제외 이유. 검색 점수와 답변 품질을 혼동하지 않는다.
평가: 기준 버전·후보 버전, 사례수, 중대 위반, 검색 적합성, 문체, 비용, p95 지연, 인간 검수자.
발행 CTA는 승인된 동일 hash의 평가가 있을 때만 가능하다. 수정 후 이전 승인 사용 금지.

## S09 로그·분석·설정
로그 필터: 시간, serviceKey, requestId, traceId, errorCode, route template, status, duration. 원문 query/body/token 수집 금지.
설정: 역할과 scope, 연동 enabled/readiness/checkedAt. 키 값은 출력하지 않는다.
내보내기는 별도 권한·대상 범위·최대 행수·만료시간을 보이며 생성 작업·다운로드 모두 감사한다.

## 공통 접근성·반응형 검증
1440/1280/768/390px, 긴 한국어 제목·ID·수치로 검사. 390px 표는 가로 스크롤과 고정 핵심 열로 접근하며 페이지 전체 넘침을 막는다. Dialog 포커스 이동·Esc·오류 안내·키보드 선택 지원. 상태는 색과 텍스트 함께 사용. 저장 중 중복 제출 차단 및 실패 후 재입력 보존.
