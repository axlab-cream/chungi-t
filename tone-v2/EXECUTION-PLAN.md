기준일: 2026-09-12. 독립 포크: `C:/Users/user/Desktop/chungi-t-tone-v2`.
사용자 승인: 전체 순차 실행, 기존 API 키 검수 사용, 부족한 자료를 ZIP 패턴과 규칙으로 보강.

## 목표와 구조

20개 서비스가 ZIP의 최신 퍼소나와 공통 규칙을 실제 고객 흐름에서 지키게 한다.
원본은 `source/`에 불변 보존한다. 생성 규칙, 검색 코퍼스, 초기/완료 리포트, 검수 도구와 화면을 한 단계씩 검증한다.
TypeScript/Node, 기존 Express API와 리포트 저장 계약을 유지한다. 결제·권한·DB 스키마 변경은 제외한다.

## 전수 작업 분해

- `TASKS.md`: ZIP 파일 82개를 각각 독립 추적하는 파일 TASK.
- `tasks/ZIP-*.md`: 각 파일의 목적, 적용 위치, 검사, 완료 조건.
- `task-index.json`: 규격·인계 문서의 본문을 행 번호와 원문을 보존한 1,500개 세부 검토 TASK로 분해.
- 세부 검토 TASK에는 제목·예문·과거 검증 기록도 포함된다. 1,500개를 모두 유효 규칙이라고 세지 않는다.
- 각 세부 TASK를 ACTIVE, SUPERSEDED, REFERENCE 중 하나로 판독한다. ACTIVE는 구현 경로·정상/반례·실제 결과 증거가 있어야 PASS다.
- SUPERSEDED는 대체 조항, REFERENCE는 운영 적용 제외 이유를 기록한다. 둘을 구현 성공률의 분자로 부풀리지 않는다.
- 파일 TASK는 자식 검토와 해당 파일의 통합 검수가 모두 끝나야 완료다.

## 확정 우선순위

1. 사용자 최신 지시: 숨김을 포함한 20개 모두 적용. 누락 자료는 보강할 수 있으나 보강임을 명시.
2. `규격/04-페르소나-상세규정.md`를 서비스 퍼소나 정본으로 사용하고 `07`과 대조.
3. 공통 규칙의 최신 개정: 체언 일반형 상한 50%, 연속 3문장 금지, 카탈로그/나열/안전 예외를 구분.
4. 과거 말투표와 도구의 값이 충돌하면 최신값으로 호환 구현. 원본 파일은 수정하지 않는다.
5. 샘플·가상 입력·과거 통과 결과는 현재 서비스 원고나 현재 검수 점수가 아니다.

### P02: 검사 도구 13개 판독·호환

- 각 도구 파일 TASK를 하나씩 읽고 입력·출력·하드코딩 서비스표·외부 실행·경로를 기록한다.

### P03: 실제 목차와 근거 연결

- 각 서비스의 운영 목차를 구조화된 정본 후보로 추출한다. 제공 목차가 발견되면 출처와 버전을 대조한다.
- ZIP과 다른 항목 수는 비교표에 남긴다. 보강 목차는 기존 운영 항목을 보존하고 ZIP의 약속·분류 패턴으로 보강한다.
- 산출물: `outlines/` 서비스별 ID/대분류/중분류/출처/보강 이유.
- 코퍼스 28팩은 블록별 개인 사실·상징·조건·금지선·수치 근거를 판독한다. 경로 전환만으로 검토 완료로 표시하지 않는다.
- 검수: 승인 목차와 실제 출력의 ID·제목·순서·항목 수 일치, 전용 검색 도메인·근거 출처 확인.

- 수정 후보: `src/report/report-generator.ts`, `report-store.ts`, `report-queue.ts`, `report-preview.ts`.

- 기존 완료 결과의 본문·ID·소유권은 불변이다. 미리보기는 실제 근거 기반으로 별도 검수한다.

- API 실호출은 합성 입력으로 격리하고 기존 운영 DB·고객 데이터는 사용하지 않는다. 키는 메모리에만 읽고 출력/저장하지 않는다.
- 먼저 한 항목으로 공급자 연결과 검수 동작을 확인하고, 실패 원인을 해결한 뒤 전체 목차로 확장한다.
