# P01 공통 규칙 §5 검수 — 항목별 고유성

검수일: 2026-09-12

## 판정 범위

- ZIP-003-047은 절 제목뿐이므로 REFERENCE/PASS다.
- ZIP-003-048~052는 생성 결과와 형제 항목을 함께 판정하는 ACTIVE 규칙이다.
- 정적 하한선은 구현했으나 실제 제공자 출력의 의미 고유성과 70개 항목 전체 체감 중복을 감수하지 않았으므로 ACTIVE 규칙은 IN_PROGRESS다.

## 구현 계약

`reviewSectionUniqueness()`를 생성 저장 전 검수에 연결했다.

1. 완료된 다른 항목과 정규화한 hook이 같으면 동일 답 재사용으로 실패한다.
2. 현재 본문의 긴 문단 중 두 개 이상이 완료된 다른 항목의 문단과 문자 3-그램 Dice 유사도 0.86 이상이면 실패한다.
3. 질문의 판별 가능한 핵심어가 없고 범용 문구 신호가 두 개 이상이면 제목 교체 가능성이 높은 원고로 실패한다.
4. `풀이 5`, `상세 풀이`, `확인한 기준`, `이 풀이에 반영한 정보`, `겁주기보다 확인 방법`을 제작용 소제목으로 실패시킨다.
5. 소제목을 사용한다면 `월급 다음 주에 새는 돈`처럼 내용을 바로 알 수 있는 생활 장면형으로 쓰도록 생성 계약에 명시한다.

## 경계와 반례

- 한 개의 긴 공통 문단만 겹치는 경우는 이 규칙만으로 실패시키지 않는다. 원국 설명처럼 불가피한 공통 근거를 과잉 차단하지 않기 위해서다.
- 문장 일부만 바꾼 긴 문단 두 개는 근접 복제로 차단한다.
- 질문 핵심어가 없는 것만으로 즉시 실패시키지 않고, 범용 문구가 함께 누적될 때만 제목 교체 가능성으로 판정한다.

## 검증 한계

- 문자 유사도는 의미가 같은 전면 재서술이나 의미가 다른데 표면이 비슷한 문장을 완벽히 구분하지 못한다.
- 항목의 의미가 실제로 달라졌는지, 장면형 소제목이 자연스러운지는 라이브 생성 결과를 사람/평가기로 검수해야 한다.
- Production 배포, 코퍼스/RAG 교체, 실제 OpenAI 생성, 릴리스 부착은 이 Task에서 실행하지 않았다.
