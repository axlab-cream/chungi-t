# P01 공통 프롬프트 §8 검수

## 범위

- 원문: `01-공통-프롬프트-규칙.md` §8
- Task: `ZIP-003-071`~`ZIP-003-076`
- 목적: 생성문 속 점수·날짜·차트 값을 서버 근거에 묶고, 점수와 시각화가 예언이나 장식으로 바뀌지 않게 한다.

## 반영 내용

- 기존 `numericEvidenceFrom` 결과를 재사용해 생성된 점수·퍼센트·연월일이 서버 근거에 있는지 확인한다.
- 서버 근거 없는 유니코드 막대·스파크라인 모양을 개인 그래프로 만들면 실패한다.
- 합격·재회·결혼·이별 등 사건의 확률/가능성으로 점수를 붙이면 실패한다.
- 해석 점수는 `적합도·주의도·우선순위` 중 하나로 이름 붙이고 산정 축과 높고 낮을 때의 의미를 함께 설명해야 한다.
- 시험·모의고사·성적처럼 사용자가 실제로 받은 점수는 해석 점수 라벨 규칙과 구분하되 숫자 자체는 여전히 서버 근거에 있어야 한다.
- 비교 점수는 정제된 context에 실제 파트너 또는 비교할 회사/직무가 있을 때만 허용한다.
- 장식 목적의 차트 또는 판단 목적이 없는 차트는 실패한다.
- Markdown 표와 차트 문장에 같은 수치가 반복되면 한 형식만 선택하도록 실패한다.

## 설계 결정

새 점수 계산기나 차트 renderer를 만들지 않았다. 생성 후 검수는 사용자 입력·서버 계산·현재 항목에서 이미 수집한 숫자 집합을 사용하므로 값의 출처가 하나다. UI의 기존 결정적 storytelling 차트는 이번 ‘공통 프롬프트 생성문’ slice에서 변경하지 않는다.

## 검증 경계

정규식은 차트가 실제로 판단을 더 쉽게 만드는지, 산정 축 설명이 충분한지, 별도 줄에 있는 표·차트 데이터가 의미상 같은지 완전히 증명하지 못한다. ACTIVE 항목은 실제 제공자 출력, 구조화된 시각화 payload, 20개 서비스 화면 의미 평가가 끝날 때까지 `IN_PROGRESS`다.
