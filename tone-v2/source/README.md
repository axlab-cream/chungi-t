## 긴 목차 실전 검증 — **5개 서비스 180항목** (2026-09-10)

`_시나리오/`의 실제 목차로 다섯 서비스를 전량 생성했다.
샘플이 서비스당 2항목이었으니 **4.5배 규모**이고, 여기서 처음으로 §5(항목별 고유성)가 시험된다.

| 서비스 | 목차 | 생성 | 누락 | 계약 | 말투 이탈 | 체언 | 5문장 | 중복 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 합격각 `pass_angle` **반말체** | 52 | 52 | **0** | **0** | **0** | 27% | 4 | 3 |
| 퇴사운 `quit_fortune` | 48 | 48 | **0** | **0** | **0** | 15% | **0** | 2 |

| | **180** | **180** | **0** | **0** | **0** | — | 13 | 8 |

**목차 누락 0 · 계약 위반 0 · 말투 이탈 0.** 180항목 전량이 목차대로 나왔다.
`wedding_day`는 전 항목 만점이다(누락·이탈·5문장·중복 전부 0).

남은 `5문장 13건`과 `중복 8건`은 **규격 위반이 아니라 편차**다 —
5문장은 자체 기준이지 계약 조항이 아니고, 중복은 180항목 중 4%다.

**계약 위반 0건.** 금지어·안전·내부용어·미래 확정·공포 전부 0이다.
안전 영역이 든 퇴사운·신년운도 통과했다 — 판정 대신 **확인과 연결**로 처리된다.

**반말체 두 서비스가 말투 이탈 0건**이다. 52항목·24항목 내내 유지됐다.
체언 비율은 15~27%로 상한 50% 안에 다 들어온다.

### ⚠️ 목차 대조는 **검사 항목이었는데 아무도 안 보고 있었다**

계약 §2.1 — *"제공된 풀이 리스트를 임의로 누락하지 않는다."*

검사 도구가 전부 **생성된 것만** 셌다. 목차와 맞춰보지 않아서 누락을 못 잡았다.
실제로 두 서비스에서 항목이 2개씩 빠져 있었고, 항목 수가 우연히 줄어서야 발견됐다.

```
newyear_flow  「지난해 정리하는 법」 · 「새해에 두면 좋은 마음가짐」
wedding_day   「남한테 좋아도 나한텐 다른 이유」 · 「나한테 유리한 결」
```

**`checkall.py`가 이제 목차를 읽어 대조한다.** 누락은 계약 위반으로 표시된다.
프롬프트에도 `이 묶음은 N개입니다. 다 쓴 뒤 세십시오`를 넣었다. **누락 4건 → 0건.**

대조는 **정규화해서** 한다. 목차의 괄호 주석(`(※ 종교 의례로 흐르지 않게)`)은
만드는 사람에게 주는 말이지 항목명이 아니다. 문자열을 그대로 비교했더니
멀쩡한 항목이 누락으로 잡혔다 — `norm()` 이 괄호·장식 기호·공백을 벗긴다.

> **교훈** — 검사기는 **있는 것**을 재기 쉽고 **없는 것**을 놓치기 쉽다.
> 계약 조항을 도구로 옮길 때 `금지`뿐 아니라 `필수`도 옮겼는지 확인해야 한다.

### 파이프라인 튜닝 값 — **규격이 아니라 생성 설정이다**

남은 셋(말투 이탈·5문장·중복)은 규격 결함이 아니라 **생성 파이프라인의 튜닝 값** 문제였다.

| 값 | 어디 | 왜 |
|---|---|---|
| **이월 창 40문장** | `mklong.py` | 24로는 52항목짜리에 모자랐다(중복 3건) |
| **문장 수 재확인 지시** | `mklong.py` | 항목이 많아지면 문장 수 통제가 느슨해진다(7%가 어긋남) |
| **숫자 비교에 말투를 묶음** | `build20.py` | 이탈 4건이 전부 `~이 큽니다` — **숫자를 다룰 때 격식체로 샌다** |
| 배치 단위 2 대분류 | `mklong.py` | 한 번에 못 만든다. 늘리면 후반 품질이 떨어진다 |
| **항목 수 확인 지시** | `mklong.py` | 프롬프트가 길어지면 뒤쪽 항목을 흘린다(§2.1 위반) |

**이 값들은 확정값이 아니다.** 목차 길이·서비스 성격에 따라 조정한다.

## 처음 검증 기록 (퇴사운 48항목)

`_시나리오/퇴사운_대분류중분류_v1.md` 의 실제 목차 **48항목**으로 전량 생성해 봤다.
지금까지 검증은 서비스당 2항목이었고, **§5(항목별 고유성)는 항목이 둘뿐이면 잴 수가 없다.**

| | 1차 | 2차 | **3차** |
|---|---:|---:|---:|
| 항목 수 | 48/48 | 48/48 | **48/48** |
| 5문장 규격 위반 | 0 | 2 | **0** |
| 계약 QA (금지어·안전·확정·공포) | 0 | — | **0** |
| 말투 이탈 | 3 | 3 | **0** |
| 말버릇 반복 | 5 | 4 | **2** |
| 체언 비율 | 6% | 9% | **15%** (상한 50%) |

**규격은 긴 목차에서 버틴다.** 안전 영역 10항목(번아웃·멘탈)도 판정 대신
**확인과 연결**로 정확히 처리됐다 — `질병이라고 단정하지는 않을게요. / 오늘 안에 상담 창구를 예약하시겠어요?`

### 배치 생성에는 **파이프라인 요구사항**이 있다

48항목을 한 번에 못 만든다. 나눠 만들면 **앞 배치가 뭘 썼는지 모른다.**
그래서 각 배치가 같은 말버릇을 처음부터 다시 쓴다 — 1차에서 5회 반복이 그렇게 났다.

| 요구 | 왜 |
|---|---|
| **앞 배치가 쓴 문장을 다음 배치에 넘긴다** | 안 넘기면 §5가 배치 경계에서 깨진다 |
| **말버릇은 배치를 지정한다** | `이 묶음에서 한 번`이라고 하면 5배치 × 1회 = 5회가 된다 |
| **안전 영역 배치는 따로 표시한다** | 체언 판정 금지(§13-6)가 배치 단위로 걸린다 |

`pilot/mkpart.py` 가 그 구조의 참고 구현이다. `python mkpart.py <1..5>` 로 배치 프롬프트를 만들고,
앞 배치 산출물에서 짧은 문장을 자동으로 이월한다.
