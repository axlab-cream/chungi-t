# 운명상회 가이드 전환 PRD

## 목적과 사용자

고객은 구매한 서비스의 고유한 인물·말투·판단 기준으로 자신의 입력과 계산에 근거한 해석을 받는다. 운영자는 원문 규격, 생성 규칙, 검색 근거와 검증 결과를 같은 버전으로 추적한다.

## 사용자 흐름과 데이터

기존 인증·프로필 입력 -> 계산 -> 해당 서비스 티저 -> 기존 권한 확인 -> 목차 항목별 생성 -> 검수 통과 항목 저장 -> 리포트 열람. 입력 원본과 계산값을 바꾸지 않는다. 이전 완료 리포트는 그대로 재조회한다.

새 자료: source inventory, persona contract, common policy, corpus review record, supplied outline, generation evidence, release manifest. 사용자·주문·결제 스키마 변경은 없다.

API는 기존 서비스 계약을 유지한다. 신규 외부 API나 권한은 추가하지 않는다. 운영자의 버전 선택은 향후 서비스 부착 시점의 새 생성에만 반영한다. 지금은 독립 포크 검증 단계다.

## 화면과 상태

기존 서비스별 입력/티저/목차/본문 화면을 사용한다. 생성 중, 입력 검증 오류, 권한 없음, 공급자 실패, 검수 실패를 구분한다. 실패를 완성된 템플릿 원고로 숨기지 않는다. 목차 항목을 고객 안내문으로 바꾸지 않는다.

공개 메타데이터/검색 노출/가격은 현재 운영 계약을 유지한다. 개인 리포트는 공개 검색 대상이 아니다. 실제 고객 입력은 샘플·Wiki에 저장하지 않는다. 기존 분석 이벤트와 버튼 동작을 보존한다.

## 미확정과 실제 자료

ZIP가 참조하는 `_시나리오`, `umsh-service-character-map.md`, `tools/qa-check.js`가 첨부에 없다. 원본 목차를 샘플로 역생성하지 않는다. 로컬에서 별도로 발견한 퇴사운 목차는 첨부와 버전 대조가 필요하다. 기존 서버 목차와 첨부의 목차 개수도 다르므로 임의로 한쪽을 정본으로 선택하지 않는다.

규격 05의 숨김 4종 제외는 사용자의 전체 적용 지시로 대체한다. 이름은 포크의 편집값에 적용하며, 시각 자산에서 추정한 나이는 실제 고객 정보로 표시하지 않는다.

2026-09-12 추가 승인: 부족한 자료는 ZIP 패턴·규칙에 따라 보강한다. 기존 목차를 출발점으로 사용하고 보강 출처·변경 이유를 따로 기록한다. 감수 도구·캐릭터 대조표 보강을 원본 감수자 자료로 표현하지 않는다. 상세 실행은 `EXECUTION-PLAN.md`, 전체 원본별 작업은 `TASKS.md`를 따른다.
