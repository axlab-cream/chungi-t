# SOLO-NARA-01 · 솔로나라 캐릭터 테스트

## 목표
`/play/solo-nara/`에서 성별 선택 → 10문항 → 로그인 → 14개 캐릭터 중 하나를 보여준다. 결과 아래에서 올해 연애운으로 보낸다.
금사빠·금사식(`love-speed`)과 같은 뼈대를 쓴다. 바뀌는 점은 MBTI·사주 판정이 빠지고, 성별 선택과 궁합이 들어가는 것뿐이다.

## 진행 순서

### 1단계 · 결정 (2026-10-06 확정)
- [x] 화면 제목은 "솔로나라에서 나는 누구?". 프로그램명은 화면에 쓰지 않는다 (테스트로 고정).
- [x] 결과 캐릭터만 GA(`result_character`)와 관리자 통계로 보낸다. 성별·답변·점수는 보내지 않는다.
- [x] 홈 THIS WEEK는 금사빠 카드를 유지하고 솔로나라 슬라이드를 추가한다. 천명상담은 항상 마지막 장.
- [x] 1200×630 배너는 사용자가 따로 만들어 전달한다. 전달 전까지 홈은 같은 비율의 HTML 카드, 운영 반영은 보류(공유 미리보기 이미지가 비기 때문).

연출 방향 (확정): CSS 애니메이션만 쓴다 (React/Framer Motion/Lottie 없음).
문항 전환 좌우 슬라이드 0.28초, 선택 시 골드 강조와 반짝임 0.26초, 선택지는 0.16초 안에 순서대로 등장하고 등장 중에도 누를 수 있다.
분석 2.7초(카드 → 성향 막대 → 이름 롤링 후 "?"에서 멈춤) → 로그인 → 돌아오면 "?" 카드가 뒤집히며 이름 공개.
"동작 줄이기" 설정이면 모든 연출을 끄고 최종 화면을 바로 보여준다.

### 2단계 · 명세 받기 (사용자)
지금 `data/solo-nara-spec.json`은 화면 확인용 임시본(`solo-nara-draft`)이다. 숫자는 검증을 통과했고, 문구는 Claude가 쓴 임시 문구다. 궁합 이유는 "(임시 문구)"로 표시돼 있다.
GPT 명세가 오면: JSON을 그 파일에 넣고 → `npm run check:solo-nara` → 필요하면 tune → `npx tsx scripts/build-solo-nara-content.ts` → 테스트.
- [ ] `backlog/solo-nara-gpt-prompt.md`를 GPT에 넣는다.
- [ ] 답변 전체와 마지막 JSON을 전달한다.

### 3단계 · 명세 검증 (Claude)
도구 준비 완료: `npx tsx scripts/check-solo-nara.ts data/solo-nara-spec.json` (구조·설계 규칙·전수 분포를 한 번에 확인, 성별당 약 1.5초).
검증 스크립트로 아래를 확인하고 숫자로 보고한다.
- JSON 구조: 캐릭터 14, 문항 8, 선택지 32, id 중복, best/danger 대상 존재
- 규칙: 기준 점수 20~80, 같은 성별 최소 거리 25, BEST·DANGER 대칭과 1:1, BEST≠DANGER, 선택지 점수 0~3, 축별 점수 폭 차이 4 이하
- 본문 표와 JSON 값 일치 (GPT가 둘을 다르게 쓰는 경우가 많다)
- 전수 계산: 성별마다 1,048,576개 조합(같은 점수 합계끼리 묶어 계산, 약 1초)

합격 기준 (전수 계산, 모든 조합을 같은 비중으로 봤을 때):
| 항목 | 기준 |
|---|---|
| 캐릭터별 비율 | 성별 안에서 각 7% 이상 25% 이하 (균등하면 14.3%) |
| 동점 비율 (1·2위 거리 차 0.5 이하) | 5% 이하 |
| 한 문항 지배 | 어떤 문항의 답 하나를 고정해도 한 캐릭터가 50%를 넘지 않음 |

주의: 실제 사람은 무작위로 답하지 않는다. 전수 계산은 "구조상 나올 수 있는지"를 보는 검사이고, 실제 분포는 출시 후 데이터로만 알 수 있다.

### 4단계 · 조정 (Claude → 사용자 확인)
도구 준비 완료: `npx tsx scripts/tune-solo-nara.ts <in.json> <out.json>`. 기준 점수만 조금씩 옮기고, 설계 규칙이 깨지는 이동은 버린다.
임시 명세로 확인한 사실: 설계 규칙을 전부 지켜도 분포는 쏠렸다(정희 34%, 영철 4%). 기준 점수 4개를 3~8점 옮기자 남녀 모두 합격. GPT 명세도 이 단계를 거친다고 보고 진행한다.
- 실패하면 **캐릭터 기준 점수만** 고친다. 문항 점수는 문구와 묶여 있어서 손대지 않는다.
- 문항 점수까지 고쳐야 하면 이유와 수정안을 먼저 보여주고 승인받는다.
- 바꾼 숫자는 표로 전후를 보여준다.

### 5단계 · 구현 (Claude)
기존 `love-speed` 파일을 기준으로 같은 자리에 만든다.
| 파일 | 내용 |
|---|---|
| `data/solo-nara-spec.json` | 검증을 통과한 GPT JSON을 그대로 둔다 (손으로 옮기지 않음) |
| `src/play/solo-nara.ts` | 완료: 명세 검사, 입력 검증(성별, 답 10개 0~3), 정규화, 거리 판정, 동점 처리, 전수 계산 |
| `src/play/solo-nara-route.ts` | 완료: 로그인 확인 후 결과 계산 POST. 사주 조회 없음. 명세가 깨져 있으면 서버가 뜨지 않음 |
| `src/server/app.ts` | `/api/play/solo-nara` 라우터 등록 (명세 도착 후) |
| `사주/사주/index.html` | 로그인 후 게임 복귀 `returnToLoveSpeedAfterAuth`에 `solo-nara` 입구 추가 |
| `package.json`, `.github/workflows/ci.yml` | `check:solo-nara` 등록 (명세 도착 후, CI 규칙상 함께 넣어야 함) |
| `사주/play/solo-nara/` | `index.html`, `preview.html`, `style.css`, `app.js`, `telemetry.js`, 공유 배너 |
| `scripts/prepare-vercel-public.mjs` | 정적 폴더 복사 한 줄 |
| `사주/portal.html` | THIS WEEK 카드 (1단계 결정대로) |
| `src/analytics/funnel-store.ts`, `admin-ui/index.html` | `solo_nara` 서비스 이름과 행동 집계 (금사빠와 같은 방식) |
| 사이트맵·메타 | 제목, 설명, canonical, OG. 결과·미리보기는 noindex |

결과 계산은 금사빠처럼 서버에서 한다. 로그인 전에는 답변을 sessionStorage에 2시간만 둔다.
공유 URL에는 `typeId`만 넣는다. 점수, 답변, 성별은 넣지 않는다.

이벤트는 기존 금사빠 규칙(`telemetry.js`)을 따른다. GA 이벤트 이름은 `solo_nara_<action>`, 관리자 통계는 `cta_click` + `solo_nara:<action>`.
action: `view`, `start`, `gender`, `progress`, `complete`, `login`, `result_view`, `share`, `share_success`, `copy`, `restart`, `fortune`.
`progress`에는 문항 번호만 붙인다. 답변 내용은 보내지 않는다.
