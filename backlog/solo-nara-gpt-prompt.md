너는 연애 심리테스트/바이럴 콘텐츠를 설계하는 10년 차 서비스 기획자이자 데이터 설계자다.

운명상회(umsh.kr)에 "나는 솔로에 출연한다면 나는 누구일까?" 테스트를 추가한다.
솔로나라 상황 8문항에 답하면, 성별에 따라 7개 캐릭터 중 하나가 결과로 나온다.

이 테스트는 AI가 결과를 즉석에서 만들지 않는다.
선택지마다 정해둔 점수를 더하고, 고정된 규칙으로 결과를 정한다.
개발자가 추가 기획 없이 코드로 옮길 수 있게 모든 숫자와 규칙을 이번 답변에서 확정해라.


# 0. 역할 분담 (먼저 읽을 것)

너의 역할:
- 캐릭터 페르소나와 결과 카피
- 캐릭터 기준 점수
- 8문항과 32개 선택지 점수
- 판정 알고리즘, 동점 규칙, 궁합
- 화면 문구, 공유 문구
- 위 내용을 담은 JSON

개발자 역할 (너는 하지 않는다):
- 65,536개 응답 조합 전수 계산과 분포 검증
- 검증 결과에 따른 캐릭터 기준 점수 미세 조정
- 이벤트 트래킹, 로그인, 화면 구현

따라서 아래 표현은 쓰지 않는다.
- "각 유형은 약 14%로 나온다", "분포가 균등하다" 같은 계산하지 않은 분포 수치
- "점수는 적절히 조절", "개발자가 정하면 됩니다", "추후 테스트하세요"


# 1. 테스트 흐름

인트로 → 성별 선택 → 8문항 4지선다 → 분석 연출 → 로그인 → 결과(캐릭터, 성향 막대, BEST/DANGER) → 공유 / 다시하기 → 연애운 CTA

- MBTI 단계는 없다.
- 사주 데이터는 판정에 쓰지 않는다. 결과 하단에서 연애운 상품으로 연결만 한다.
- 연애운 CTA 문구: "올해 내 연애운 확인하기"
- 연애운 CTA 주소: https://umsh.kr/love/this-year/01-step-1-story/index.html


# 2. 성별 선택

질문: "솔로나라에서 어떤 이름을 받을까?"
- 여자 이름으로 테스트하기 → 결과 후보: 영숙, 정숙, 순자, 영자, 옥순, 현숙, 정희
- 남자 이름으로 테스트하기 → 결과 후보: 영수, 영호, 영식, 영철, 광수, 상철, 경수

성별은 결과 후보군만 정한다. 문항과 점수 계산은 남녀가 똑같다.


# 3. 캐릭터 페르소나

기본 방향:

여성
- 영숙: 적극적, 주도적, 감정 표현이 분명함
- 정숙: 신뢰, 안정, 책임감
- 순자: 밝음, 친화력, 즉흥성
- 영자: 감성, 공감, 관계 중심
- 옥순: 자신감, 선택 기준이 분명함, 독립성
- 현숙: 현실적, 균형, 판단력
- 정희: 여유, 관찰, 신중함

남성
- 영수: 안정, 책임, 신뢰
- 영호: 유머, 친화력, 편안함
- 영식: 섬세, 배려, 헌신
- 영철: 직진, 열정, 높은 표현력
- 광수: 분석, 독특함, 자기 세계
- 상철: 자유, 독립, 자연스러운 매력
- 경수: 관찰, 신중, 확신 중시

실제 방송 출연자의 성격이나 사건은 가져오지 않는다. 각 이름을 독립된 가상 연애 유형으로 설계한다.

캐릭터마다 작성할 항목:
- typeId (영문 소문자, 예: oksun)
- name
- oneLiner: 한 줄 캐릭터 정의
- keywords: 핵심 키워드 3개
- title: 결과 제목
- description: 결과 설명 3~4문장
- strength: 연애할 때 강점
- weakness: 연애할 때 주의점
- tip: 연애 팁 한 줄
- shareText: 공유 문구 (예: "나는 솔로나라에 들어가면 옥순?! 너는 어떤 이름일지 테스트해봐 👀")
- best, bestReason, danger, dangerReason (5번 궁합 규칙을 따른다)

좋은 캐릭터 / 나쁜 캐릭터 구조를 만들지 않는다. 모든 캐릭터의 약점은 고칠 수 있는 습관으로 쓰고, 비하하지 않는다.


# 4. 성향 축과 기준 점수

## 4-1. 축 4개

- direct (직진도): 낮음 = 확신이 생긴 뒤 움직임 / 높음 = 호감이 생기면 먼저 다가가고 빠르게 진행
- express (표현력): 낮음 = 호감을 잘 드러내지 않음 / 높음 = 호감과 감정을 적극적으로 표현
- stability (안정 추구): 낮음 = 설렘, 순간의 감정, 새 경험 중시 / 높음 = 신뢰, 장기 관계, 현실 궁합 중시
- independence (독립성): 낮음 = 상대와 관계 분위기를 우선 / 높음 = 자기 기준, 자기 생활, 개인 영역을 우선

## 4-2. 기준 점수 규칙

캐릭터마다 4개 축 값을 정수로 정한다.

1. 모든 값은 20~80 사이다. 0~19, 81~100은 쓰지 않는다.
   이유: 사용자 점수는 가운데 쪽에 몰리기 쉬워서, 극단값에 놓인 캐릭터는 거의 나오지 않는다.
2. 같은 성별 7명 안에서, 각 축마다 35 이하인 캐릭터가 2명 이상, 65 이상인 캐릭터가 2명 이상 있어야 한다.
3. 같은 성별 안에서 어떤 두 명을 골라도 4축 유클리드 거리가 25 이상이다.
4. 정숙 / 현숙 / 정희, 영수 / 경수는 서로 최소 한 축에서 30점 이상 차이 난다. 어느 축에서 왜 갈리는지 한 줄로 설명한다.
5. 캐릭터마다 "이 점수인 이유"를 한 줄로 쓴다.
6. 같은 성별 7×7 거리표를 여성, 남성 각각 출력한다. 거리는 소수점 첫째 자리까지.


# 5. 궁합 규칙

- 여성은 남성과, 남성은 여성과 연결한다.
- BEST는 상호 대칭이다. 옥순 BEST = 상철이면 상철 BEST = 옥순. 결과적으로 BEST 커플 7쌍이 된다. 한 사람이 BEST 쌍에 두 번 들어가지 않는다.
- DANGER도 상호 대칭이고, DANGER 커플 7쌍이 된다. 한 사람이 DANGER 쌍에 두 번 들어가지 않는다.
- 한 캐릭터의 BEST와 DANGER는 서로 다른 사람이다.
- 이유는 1~2문장. 단순히 점수가 비슷해서 잘 맞는다고 쓰지 말고, 보완 관계, 갈등 가능성, 관계 텐션, 표현 방식 차이를 4개 축 점수와 연결해서 쓴다.
- DANGER는 "절대 안 맞는다"가 아니라 "부딪히기 쉬운 지점"으로 쓴다.


# 6. 문항

## 6-1. 상황

8문항 모두 솔로나라 안에서 벌어질 법한 장면으로 쓴다. 아래 8개 장면을 한 번씩 쓴다.
첫인상 선택 / 첫날 저녁 / 관심 상대와 대화 / 관심 상대가 다른 사람과 데이트 / 1:1 데이트 / 경쟁 상대 등장 / 호감 확인 / 최종 선택

## 6-2. 문장

- 주어가 분명해야 한다. 누가 누구에게 하는 행동인지 헷갈리지 않게 쓴다.
- 중고등학생도 한 번에 읽히는 쉬운 말로 쓴다. 유치한 말투는 쓰지 않는다.
- 질문은 30자 이내(줄바꿈 1회 허용), 선택지는 20자 이내.
- 선택지만 보고 "이건 무조건 옥순"처럼 결과가 보이면 안 된다.
- 좋은 답 / 나쁜 답 구조를 만들지 않는다. 네 선택지 모두 실제로 고를 법해야 한다.

## 6-3. 점수

- 선택지 점수는 축마다 0~3 정수다.
- 문항마다 주요 측정축을 1~2개 정하고 표에 적는다. 주요 측정축은 네 선택지 중 0점과 3점이 모두 나와야 한다.
- 주요 측정축이 아닌 축은 0~1점만 쓴다.
- 4개 축 각각이 8문항 중 최소 3문항에서 주요 측정축이 된다.
- 축별 (최대 가능 합계 − 최소 가능 합계)를 계산하고, 네 축 사이의 차이가 4 이하가 되게 맞춘다.


# 7. 정규화와 판정

## 7-1. 정규화

축별로 실제 점수표 기준 최소 가능 합계(min)와 최대 가능 합계(max)를 계산해 표로 적는다.

normalized = round((raw − min) / (max − min) × 100, 1)

## 7-2. 판정

1. 사용자 벡터 u = [direct, express, stability, independence] (정규화 값)
2. 성별 후보 7명 각각의 기준 벡터 c와 거리 d = sqrt(Σ (u_i − c_i)²)
3. 거리가 가장 작은 캐릭터가 결과다.

의사코드와, 예제 답변 1세트(A/B/C/D 8개) → raw 점수 → 정규화 → 7명 거리 → 결과까지 실제 숫자로 보여준다. 예제는 여성, 남성 각 1개.

## 7-3. 동점 처리

- 1위와 2위의 거리 차이가 0.5 이하이면 동점으로 본다.
- 2차: 두 캐릭터 각각의 "대표 축"(캐릭터마다 1개 지정)에서 사용자 점수와의 차이가 더 작은 쪽.
- 3차: 그래도 같으면 미리 정한 순서. 순서는 특정 캐릭터가 유리하지 않게 정하고, 그렇게 정한 이유를 쓴다.
- 캐릭터마다 대표 축을 표로 적는다.


# 8. 화면 문구

모든 문구는 가볍고 연애 예능 느낌으로, 쉬운 말로 쓴다. 과한 유행어와 촌스러운 표현은 피한다.

- 시작 화면: 메인 타이틀, 서브카피, 시작 버튼
- 성별 선택 화면: 질문, 버튼 2개
- 분석 연출: 3단계 문구 (전체 2~3초 동안 순서대로 보여줌)
- 로그인 직전: 기본 문구 "당신의 솔로나라 이름을 찾았어요. 결과를 보려면 로그인해주세요." + 대체 문구 2개
- 결과 화면 고정 문구: 상단 "당신이 솔로나라에 들어간다면", 성향 막대 이름(직진력/표현력/안정 추구/독립성), 연애운 연결 문구 템플릿("연애 성향은 {name}, 그렇다면 올해 연애운은?" 형태), 다시하기 / 공유하기 버튼
- 면책 문구: "본 테스트는 재미를 위한 비공식 성향 테스트이며 특정 방송사, 프로그램 및 출연자와 관련이 없습니다."
- 홈 배너(THIS WEEK 카드): eyebrow, headline, description, CTA
- 카카오톡 공유 미리보기: 제목, 설명


# 9. 개발자 검수 체크리스트

분포 수치는 쓰지 말고, 개발자가 전수 계산 때 확인할 항목만 적는다. 아래 항목을 포함한다.
- 결과로 한 번도 안 나오는 캐릭터
- 지나치게 자주 나오는 캐릭터
- 결과 영역이 거의 겹치는 두 캐릭터
- 동점(0.5 이하) 발생 비율
- 한 문항이 결과를 혼자 좌우하는지
그리고 위 항목이 실패했을 때 기준 점수를 어느 방향으로 고치면 되는지 캐릭터별로 한 줄씩 적는다.
