## 1. 결과와 파일 사용 순서

기존 자료는 서비스별 제목은 달랐지만, 본문이 ‘자네·하네·일세’와 동일한 생년·오행·고민 소개를 반복해 캐릭터 차이가 약했다. 원문을 따라 말투 어미만 바꾸는 대신 **무엇을 먼저 보고, 감정을 어떻게 받고, 어떤 장면을 설명하며, 무엇으로 끝낼지**를 서비스별로 다시 설계했다.

새로 작성한 파일은 다음 세 개다. 원본 Markdown과 18개 PDF는 수정하지 않았다.

| 파일 | 용도 | 적용 범위 |
|---|---|---|
| `prompt_guides_18_revised.md` | 시스템 프롬프트용 공통 규칙·서비스별 규칙 | 공통 블록 + 요청된 서비스 블록 한 개 |
| `interpretations_18_revised.md` | 문체와 구성의 적용 예시 | 18개 서비스, 148개 소주제의 통합 개정문 |
| `review_18_report.md` | 원본 문제·처리 근거·검수·남은 확인 사항 | 편집·운영 참고용 |

해석문은 604쪽을 같은 분량으로 재생성한 PDF가 아니다. 반복된 소개·결론·다중 분기를 합쳐 **주제 단위로 다시 쓴 Markdown 통합본**이다. 원본 레이아웃·각 카드와 일대일로 대응하는 PDF 출력물은 만들지 않았다. 아래 대응표로 기존 주제의 처리 위치를 확인할 수 있다.

새 가이드에는 명리 해석을 포기하라는 규칙을 넣지 않았다. 검증된 명식·십성·운 흐름이 있으면 그것을 근거로 해석하되, 이번 원본처럼 서로 충돌하거나 입력이 비어 있는 부분은 실제 계산 결과처럼 꾸미지 않도록 했다. 예시집의 해당 문단은 이 제한을 드러내므로, 계산 근거가 보완되면 개인 해석 부분을 더 구체화할 수 있다.

### 4-1 공통 프롬프트 자체의 충돌

| 원본 위치·표현 | 문제 | 개정 처리 |
|---|---|---|
| 공통 규칙 ‘어미를 섞지 않는다’와 천명사주 예시 `하네, 보게, 입니다` | 자체 지시 충돌 | 높임말 체계 통일. 인용된 실제 메시지만 별도 말투 허용 |
| 직장선택·이직운 `입니다, 확인하게`, 재회운 `입니다, 바뀌어야 하네` | 현대 캐릭터에도 도사체 혼입 | 직장선택 합니다체, 이직·재회는 각각 목적이 다른 해요체 |
| 천명사주 ‘묵직하고 원숙한 스승’ | 공개 캐릭터의 젊고 절제된 인상과 거리 | 늙은 훈장식 상투어를 빼고 차분한 자신감 유지 |
| 고양이궁합 `일지(日旨)` | 한자 오기와 비유의 정의화 | `일지(日支, 태어난 날의 지지)`로 교정 |

| ‘한 문장 1~2줄’, ‘3줄 이상 장문 금지’ | 기기·폰트에 따라 달라지는 줄 수 | 한 문장 한 생각, 의미 단락과 빈 줄 기준 |
| 줄바꿈을 Text RAG 최적화의 중심으로 제시 | 문장의 적용 조건·서비스 분리보다 형식에 치우침 | 검색 문장의 적용 조건, 내부 필드 제거, 타 서비스 혼입 검수 추가 |
| 필수 한자와 세 가지 행동의 반복 | 모든 항목이 같은 읽기 경험 | 처음 등장하는 전문용어 풀이, 독립 카드 예외, 마무리 유형 다양화 |

## 6. 실제 적용 방식

1. 공통 블록은 `COMMON_SYSTEM_BEGIN`과 `COMMON_SYSTEM_END` 사이 본문을 사용한다.
2. 서비스는 원본 식별자에 맞는 `SERVICE_SYSTEM_BEGIN:키`와 종료 표시 사이 본문을 하나만 사용한다.
3. 관찰표·비교표·이 보고서는 운영 참고 자료다. 매 응답의 시스템 본문에 전부 넣지 않는다.
4. 현재 사용자 정보·기준일·검증된 계산값·해당 서비스의 참고문을 기존 입력 구조로 전달한다. 이 문서의 표가 새 API 스키마는 아니다.
5. 예시집은 선택한 서비스의 문체만 참고한다. QA 사례의 이름·회사·고양이·날짜·목표 금액을 실제 고객의 사실로 복제하지 않는다.
6. 계산 자료가 없는 경우에는 해당 해석의 범위를 짧게 알리고, 확인된 질문에 답한다. 반복 면책문으로 본문을 채우지 않는다.

특히 `love_this_year`와 공개 입력 경로에서 보이는 `love_thisyear` 같은 별칭은 기존 서비스 매핑을 확인해야 한다. 이번 작업에서 라우트·키·API 매핑은 변경하지 않았다.

## 7. 검증 결과와 남은 확인

### 문서 검증

- 가이드의 18개 서비스 식별자가 모두 원본에 존재하며 중복이 없음을 확인했다.
- 공통 블록 1쌍, 서비스 블록 18쌍의 시작·종료 일치를 확인했다.
- 예시집 18개 장·148개 소주제의 연속 번호를 자동 검사하고 대응표를 수동 대조했다.
- UTF-8 읽기, 대체 문자·널 문자 없음, 코드 펜스 균형과 파일 참조를 확인했다.
- 말투 대조 중 오늘운의 격식체 혼입과 합격각·결혼궁합의 가이드/예시 차이를 발견해 정리했다. 도사체는 천명사주·합격각에 한정했다.
- 예시집에서 내부 필드, 깨진 조사와 다른 일간 참고문이 제거됐음을 검사했다. 사례는 서비스별로 분리하고 조건별 설명은 별도 표시했다.
- 공식 시험 형식·명식·용신이 확인되지 않은 부분은 계산 결과로 확정하지 않았음을 대조했다.

이 항목의 실행 결과는 문서 구조 검사 및 수동 대조 기준이다. 모델에 실제 호출하여 여러 번 생성한 출력의 통과 결과를 뜻하지 않는다.
