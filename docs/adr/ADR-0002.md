# ADR-0002: 운영 관리자 UI 배치와 디자인 방향

## Status

Proposed — T01(`docs/admin-ops/T01-baseline.md`) 조사 결과에 근거함.
U3(관리자 UI 단일 소스 위치)의 결정 후보이며, T07 착수 전 확정한다.

## Context

`admin-ops-execution-pack`의 ADR-11은 관리자 UI 기술을 "기존 정적 UI 우선"으로
제안하되 실제 배치는 저장소 관례 확인 후 정하라고 남겨두었다.
T01에서 확인한 배포 구조는 다음과 같다.

- `vercel.json`의 `rewrites`가 모든 경로를 `/api/index`로 보낸다. 따라서 `/admin`은
  Express 앱에 도달한다.
- `vercel.json`의 `includeFiles: "{data,prompts,사주}/**"`가 `사주/**`를 함수 번들에
  포함시킨다. `src/server/app.ts`는 말미(683~684행)에서 `express.static(SAJU_UI)`,
  `express.static(SAJU_ROOT)`를 catch-all로 마운트한다.
- `scripts/prepare-vercel-public.mjs`가 일부 파일을 `public/`으로 복사한다.
  Vercel은 `public/`의 실제 파일을 rewrite보다 먼저 매칭할 수 있어, 같은 경로가
  두 소스에 존재하면 어느 쪽이 서빙되는지 불분명해진다.
- `src/server/app.ts`에 `'/admin`으로 시작하는 라우트 등록은 0건이다. 경로는 비어 있다.

디자인 방향은 사용자가 `C:\Users\user\Desktop\preview.html`을 참조로 지정했다.
이 파일은 SK매직몰 상품목록 페이지를 기준으로 정리한 비공식 UI·브랜드 레퍼런스
가이드이며, `:root`에 48개 CSS 커스텀 프로퍼티(색·간격·radius·타이포)를 정의하고
"넓은 여백 / 가격 위계 / 절제된 레드 / neutral first, red with intent" 원칙과
상품 카드 정보 순서, 1200px 그리드 규범을 문서화한다.

기본 시각 방침인 `white-editorial-canvas`는 "사용자가 더 강한 방향을 주지 않은 경우"에
적용된다. 이번에는 사용자가 명시적 참조를 제공했으므로 그 방향이 우선한다.

## Decision

### D1. 관리자 UI 소스 위치 — 정적 루트 **밖**에 둔다

관리자 UI 소스를 **`admin-ui/`(저장소 루트 직하, `사주/`·`public/` 밖)** 에 둔다.
`vercel.json`의 `includeFiles`에 `admin-ui`를 추가하고, 서빙은 **인증 미들웨어를 통과한
전용 라우트에서만** 한다. `prepare-vercel-public.mjs`의 `public/` 복사 대상에 넣지 않는다.

> **초판 정정 (Codex 리뷰 반영).** 초판은 `사주/admin/`을 단일 소스로 제안했다. 이는 위험하다.
> `src/server/app.ts:684`의 `app.use(express.static(SAJU_ROOT, { index: false }))`가
> `사주/` 아래 실제 파일을 **인증 검사 없이** 그대로 서빙한다. 즉 관리자 HTML/JS를
> `사주/admin/`에 두면 `/admin/dashboard.html` 같은 직접 요청이 정적 미들웨어에서
> 처리되어 권한 검사를 우회한다. 라우트 등록 순서를 조정해도 “실수로 정적 루트에 파일을
> 추가하면 노출되는” 구조적 위험이 남는다. 정적 루트 밖에 두면 이 위험 자체가 사라진다.

`index: false`이므로 `/admin` 자체에 대한 응답은 명시적 라우트로 만들어야 한다.

### D2. 라우트 등록 순서와 정적 자산 처리

1. `/api/admin/v1` 라우터는 기존 `app.use('/api', …)` 미들웨어(196행) **아래**,
   즉 `/api` 접두어 안에 둔다. 그러면 `Cache-Control: private, no-store` +
   `Vary: Authorization`이 자동 적용되어 09-API의 no-store 요구를 충족한다.
2. `/admin` 라우터(HTML 진입점 + 정적 자산)는 `express.static` catch-all(683~684행)
   **위에** 등록한다. 이는 “뒤 라우트가 전부 가려지기 때문”이 아니라,
   같은 경로의 정적 파일이 먼저 매칭되는 경우를 원천 차단하기 위한 것이다.
3. `/admin` 정적 자산은 **인증 미들웨어 뒤**에서만 서빙한다.
   순서: 직원 세션 검증 → 역할·scope 확인 → 정적 응답.
4. 딥링크·SPA fallback: `/admin/*` 미매칭 경로는 정적 탐색으로 흘리지 않고
   인증 상태에 따라 로그인 리다이렉트 또는 관리자 셸 HTML로 응답한다.
5. 관리자 정적 자산에는 **어떤 설정값·키·엔드포인트 비밀도 인라인하지 않는다.**
   런타임 설정은 인증된 `GET /api/admin/v1/me` 응답으로만 전달한다.

#### 커버해야 할 실패 모드

| 실패 모드 | 대응 |
| --- | --- |
| 정적 미들웨어가 인증 전에 관리자 파일을 서빙 | D1(정적 루트 밖) + D2-2 |
| `/admin` 직접 URL 접근 (미로그인) | 401/리다이렉트, 데이터 없음 (A01) |
| `/admin/*` 딥링크 미매칭 | D2-4 |
| 권한 회수 후 캐시된 관리자 자산 재사용 | 자산에 비밀 없음(D2-5) + API가 매 요청 membership 확인 (A03) |
| 검색엔진 노출 | `X-Robots-Tag: noindex`, robots 차단, 미리보기 토큰은 비공개·만료 |

### D3. 디자인 — 원칙만 차용하고 토큰은 독립 정의한다

> **초판 정정 (Codex 리뷰 반영).** 초판은 `preview.html`의 색상값(`#ea1738` 등)과
> 토큰 이름을 그대로 채택했다. 로고·카피·이미지를 제외해도 **동일한 색상값과 조합을 쓰면
> 레퍼런스와 시각적으로 닮는다.** 내부 전용이라 노출 위험은 낮지만 그 자체로
> 브랜드 모방 위험이 사라지지는 않는다.

채택하는 것 — **레이아웃·밀도·접근성 원칙** (수치가 아닌 규범):

- neutral first: 무채색이 기본이고 유채색은 의도가 있을 때만 쓴다.
  관리자에서는 이를 더 강하게 적용해 **강조색은 상태 색이 아니라 조치 색**으로 쓴다.
  실패·경고 상태는 회색/앰버 계열 + 텍스트 라벨로, 되돌릴 수 없는 버튼만 경고색으로 둔다.
- 금액 위계: 금액은 KRW 정수 + 원 단위 + `font-variant-numeric: tabular-nums`.
  승인액/환불액/순액을 같은 정렬축(우측 정렬, 동일 자릿수 폭)에 둔다 (06-SCREENS S01).
- 여백 운용: 여백은 **섹션 간**에 쓰고 표 행 높이는 압축한다. 운영 표는 밀도가 우선이다.
- 컨테이너: 폼·상세 화면은 좁은 고정폭, 표 중심 화면은 넓은 폭 두 단계.
- 반경: 관리자는 작은 반경 한 단계만 쓴다. 큰 반경(카드형 24px 계열)을 쓰지 않는다.
- 간격: 4px 배수 스케일 한 벌로 통일한다.

채택하지 않는 것:
- `preview.html`의 **구체적 색상 hex 값과 토큰 이름**(`--sk-*` 포함)
- 레드-오렌지-옐로 강조 조합
- 로고, 브랜드 카피, 이미지, 상품 카드 레이아웃
- 웹폰트 CDN 경로 (`static.skmagic.com`)

관리자 팔레트는 **의미 기반 토큰 이름으로 독립 정의**한다:

```
--admin-bg, --admin-surface, --admin-line
--admin-text, --admin-text-muted, --admin-text-disabled
--admin-state-ok        정상·완료·승인
--admin-state-warn      주의·불확정 (PG unknown, 대사 차이, 재시도 필요)
--admin-state-error     실패
--admin-action-danger   되돌릴 수 없는 조치 전용 (환불 실행, 삭제, 권한 회수)
--admin-focus           키보드 포커스 링
```

실제 색상값은 T07 착수 시 **대비비(WCAG AA 이상)를 먼저 만족시키는 조건으로 새로 고르고**,
`design-system/MASTER.md`에 근거와 함께 기록한다. 시각 검토를 거쳐 레퍼런스와
구분되는지 확인한 뒤 확정한다. 서체는 프로젝트에 이미 쓰는 한국어 서체 스택을 따르고
새 CDN을 추가하지 않는다.

### D4. 상태 표현

13-SECURITY와 06-SCREENS 공통 요구에 따라 **색 단독 표현을 금지**한다.
모든 상태는 `색 + 텍스트 라벨`을 함께 쓴다. 06-SCREENS의 A35 요구대로
빈 목록 / 필터 결과 없음 / 조회 실패 / 권한 없음을 서로 다른 UI 상태로 구분한다.

### D5. 반응형·접근성 기준

검증 폭은 1440 / 1280 / 768 / 390px이며 긴 한국어 제목·ID·수치로 검사한다.
390px에서 표는 가로 스크롤 + 핵심 열 고정으로 처리하고 페이지 전체 넘침을 막는다.
표를 의미 없이 카드로 변환하지 않는다(05-IA 공통 리스트 규격).

## Consequences

- `vercel.json`의 `includeFiles`에 `admin-ui`를 추가해야 한다. 이는 `vercel.json` 변경이므로
  T07에서 함께 검증한다. 번들 크기 증가분은 관리자 자산 크기만큼이다.
- 관리자 자산이 정적 루트 밖에 있으므로 **모든 관리자 응답이 반드시 인증 라우트를 지난다.**
  실수로 파일을 정적 루트에 추가해 노출되는 사고 유형이 구조적으로 제거된다.
- 디자인 토큰을 새로 정의해야 하므로 T07의 작업량이 초판 계획보다 늘어난다.
  대신 레퍼런스 종속성과 브랜드 모방 위험이 제거되고 대비비를 처음부터 설계에 넣는다.
- `design-system/MASTER.md`가 아직 없다. T07 착수 시 D3의 의미 기반 토큰 목록을 근거로
  생성한다 (web-design-skills 워크플로우 7단계).

## Open

- U3는 이 ADR 승인으로 해소된다. 승인 전에는 T07을 시작하지 않는다.
- 관리자 미리보기 토큰(05-IA "비공개·만료 토큰, 검색엔진 미노출")의 구현 방식은
  T07에서 별도 결정한다.
- 실제 색상값은 T07에서 대비비 검증과 함께 확정한다. 이 ADR은 값을 고정하지 않는다.

## Review

D1(정적 자산 인증 순서)과 D3(디자인 경계)을 재작성했다. 반려한 지적은 없다.
