# PRD — 저축운 실제 데이터 무료 티저 운영 적용 (2026-09-28)

## 문제

`money/save` 무료 결과는 정적 키비주얼·고정 12% 요약·가격 CTA를 표시해 저장된 회원 입력과 서버 해석 1·2번을 충분히 보여주지 못했다. 실제 목차, 조회 횟수, 결제 경계도 직장 선택의 최신 공통 패턴과 달랐다.

## 사용자 결과

- 로그인 회원은 저장 사주와 저축운 사전 입력으로 생성된 해석 1·2번만 무료로 읽는다.
- 각 장은 서로 다른 실제 이미지, 개인화 제목과 도입, 800자 이상의 본문, 실제 입력 표 또는 서버 계산 오행 차트, 확인 장면·질문·결론을 갖는다.
- 첫 장에는 수입→저축 목표→직접 짚은 지출의 적용 순서를, 둘째 장에는 결제 간격 또는 관계 정산 순서를 실제 값으로 시각화한다. 입력 표는 값 복사에 그치지 않고 각 값이 풀이에서 맡는 역할까지 연결한다.
- 첫 화면과 본문은 입력을 불러온 방식이나 해석의 한계를 설명하지 않고, 고객이 직접 짚은 돈 문제와 통장에서 반복되는 장면을 먼저 명확하게 말한다.
- 3번부터 마지막 실제 목차는 기본 펼침 상태이며 제목·분류·잠김만 공개한다.
- 잠금 목차 아래에는 조회 횟수와 CTA가 한 번만 나타난다.
- 5회 한도는 기존 영속 RPC를 사용하되 직장 선택과 저축운을 분리하고, 같은 입력 재열람은 다시 차감하지 않는다.

## 데이터 경계

- 사용 값: 저장 생년월일시 분석, `moneyHabit`, `incomePattern`, `leakPoint`, `relationSpending`, `savingGoal`, `concern`, 서버 계산 `elementCount`.
- 사주 근거는 서버가 계산한 네 기둥의 기운 구성, 태어난 날의 중심 기운, 다섯 기운 분포를 사용한다. 한자 기둥값은 화면에 노출하지 않고 해·달·날·시간의 생활 역할로 풀어 쓴다.
- 입력되지 않은 금액·횟수·예산 비율·사건은 만들지 않는다.
- 무료 응답에는 1·2번 본문만 포함하고 3~N은 TOC 메타데이터만 반환한다.
- 유료 저장 원문, 결제, 보관함, 인증 계약은 유지한다.
- DB 스키마 변경 없이 이미 배포된 조회 영속 저장소를 서비스별 키로 분리한다.

## 수용 기준

1. 실제 해석 1·2, 서로 다른 이미지, 마크다운, 표와 차트가 표시된다.
2. 내부 QA·샘플 문구, 원시 마크다운, 한자 병기, 정적 가격 카드가 보이지 않는다.
3. 실제 3~N 목차가 기본 펼침·잠김이며 공개 본문 및 CTA와 중복되지 않는다.
4. `전체 목차 열기`는 미결제 회원에게 서버가 발급한 개인 결제 URL을 열고, 결제·관리자 권한이 확인된 회원에게만 저장 리포트 목차를 연다.
5. `입력값 다시 확인`은 무료 조회 횟수와 같은 상태 행에 두고 구매 CTA와 분리한다.
6. 조회 사용/잔여 횟수가 5회 기준 실제 API 값으로 표시된다.
7. 모바일에서 표·차트가 화면 밖으로 넘치지 않고 하단 내비게이션이 CTA를 가리지 않는다.
8. 전체 회귀, 타입, production build, 독립/수동 리뷰, 배포 및 운영 URL 검증을 통과한다.
9. 첫 화면에 `적어 주셨습니다`, `비교 설명`, `해석을 연결합니다` 같은 내부 절차형 문구가 노출되지 않는다.
10. 430px 이하에서 3열 표는 항목별 카드로 재배치되고, 순서도·오행 차트의 값과 설명을 색상 없이도 읽을 수 있다.
11. 네 기둥 표와 본문이 같은 실제 계산값을 사용하며, 사주 근거와 사용자가 직접 입력한 소비 사실을 구분해 연결한다.
