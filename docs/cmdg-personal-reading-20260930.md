# 천명사주 개인 고민 중심 읽기

## 요구·판정
- R1: 계산된 네 기둥·오행·명리·대운을 장의 질문에 연결한다. 자미두수 계산은 현재 없으므로 사용했다고 주장하지 않는다.
- R2: 전체 이직 결론을 연애·성격에 강제하지 않는다. 단순 오행 개수와 지장간 가중치를 구별한다.
- R3: 안전한 마크다운, 핵심 밑줄, 모바일 표 줄바꿈, 실제 계산 차트를 제공한다.
- R4: 장별 추가 질문 → 본인·결제 권한 확인 → 저장된 계산과 해당 장으로 답변 → 리포트 부가 이력 저장/재조회.
- R5: 연애 장의 버튼 → GPT Image 2 → 비공개 이미지 저장 → 본인만 조회. 미래 인물 예측이 아닌 상상 스케치라고 명시한다. 출생 원문·실명·회사는 이미지 모델에 보내지 않는다.
- 완료된 본문/입력/결제 계보는 불변. 새 답변은 부가 이력으로 남긴다. 재생성은 자동 실행하지 않는다.

## 조사
- calculator.ts: 음양력 변환, 절기와 출생시각을 통한 기둥 계산.
- analyzer.ts: 오행 개수/지장간 가중, 십신, 합충, 조후와 용신 추정, 대운.
- report-generator.ts: 모든 장에 fixedVerdict 강제. 주제별 분리보다 전체 고민을 반복할 원인.
- 공용 리더의 '추가로 확인할 것'은 고정 편집 문장. 회원 생활 입력은 GET 응답에서 시각화에만 연결되고 생성 프롬프트에는 없음.

## 구현 계획
1. 장별 생성 계약과 회귀 테스트: 천명사주만 고정 결론 강제 해제, 질문 중심 문체·마크다운, 실제 계산 근거.
2. 장별 추가 상담 API: 기존 소유권/결제 검사, 입력 길이 검증, 완료 본문 보존, CAS 잠금과 요청 중복 억제, 최근 답변 재조회.
3. 이미지 API: 연애 장만 허용, 1리포트 1장 재사용, 비공개 Storage, GPT Image 2 WebP, 재시도/실패 상태.
4. 공용 리더: 추가 질문과 스케치 UI, 핵심 밑줄, 표 모바일 적합성, 회원별 상태 리셋.
5. 집중·전체 회귀/타입/빌드/모바일 검증 후 기록. 운영 변경과 외부 모델 실호출은 실제 실행 여부를 별도 보고.

## 시각 방향
기존 검정·금색 유지: 배경 #050403, 패널 #14100d, 본문 #fff7df, 보조 #c6bdad, 강조 #e8c76f.
한 줄 답은 금색 밑줄, 근거는 읽기 쉬운 본문, 질문은 장 끝에 배치한다. 표는 고정 폭·셀 줄바꿈, 수치는 계산값만 사용한다.

## 검증 및 운영 인계 (2026-09-30)
- 새 천명사주 본문은 네 소제목의 누락/중복/역순을 완료 불가 결함으로 처리한다. 짧은 하이라이트는 지정 문단 수 안에서 동일한 서사 순서를 유지한다.
- 기존 저장 본문은 변경하지 않았다. 새 생성 계약과 장별 추가 상담으로 개선하며, 과거 본문 일괄 재생성은 별도 작업이다.
- 개인화: 저장된 사주 계산, 선택한 장의 원문, 직접 입력 질문, 주제별 회원 생활정보. 연애 장에서 무관한 직장 고민을 제외한다.
- 로컬 합성 데이터 브라우저 검증: 320/375/390/430/1280px, 표 셀 및 문서 가로 넘침 0; 네 답변 단계/강조/질문 전송/새로고침 후 답변 재표시 확인.
- API 통합 검증: 비로그인/타인/미결제 거절, 완료된 장만 질문, 중복 동시 호출 차단, 저장 답변 재사용, 일일 요청 제한, 이미지 비공개 인증 조회. 외부 모델·Storage는 테스트 대역이며 운영 실호출 성공을 의미하지 않는다.
- 코드 검토에서 요약문 문단 수와 본문 네 소제목 충돌, 초기 답변 로딩 경쟁을 발견하고 수정했다.
- API 추가: /api/report/:reportId/reader, /question, /sketch. 기존 auxiliary에 답변/이미지 메타데이터 저장. DB 스키마 변경 없음.

## 배포 전 필요한 설정과 제한
- 서버 환경: OPENAI_API_KEY, SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY. REPORT_SKETCH_BUCKET 기본값 report-sketches.
- Storage에 비공개 report-sketches 버킷이 필요하다. public=false를 서버가 확인한 다음에만 이미지 생성 비용을 지출한다. 키는 프런트에 전달하지 않는다.
- 이미지 요청은 gpt-image-2, 1024x1024, WebP, low. 리포트당 1장 생성 후 재사용한다. 이름/생년월일/회사/질문 원문은 이미지 프롬프트에 포함하지 않는다.
- 이미지 생성과 질문의 합계 일일 8회 요청 상한, 리포트별 동시 작업 1개, 10분 잠금 만료. 이미지의 성별 표현 변경에 따른 재생성은 제공하지 않는다.
- 이미지 업로드 후 DB 저장 실패 또는 리포트 삭제 시 비공개 고아 객체의 운영 정리 정책은 후속 필요. 저장 키는 소유자/리포트/작업 ID로 분리된다.
- 운영 버킷 생성, 원격 push/배포, 실제 GPT Image 2 호출, 실제 운영 회원 검증은 아직 실행하지 않았다. rules.md §6.3에 따라 이 천명사주 변경의 운영 반영 범위를 확인한 뒤 실행한다.
- 공식 API 근거: https://developers.openai.com/api/docs/guides/image-prompting (GPT Image 2 및 WebP 인자).

## 목차 충실도 후속
- 사용자가 목차 확장을 허용했다. 현재 16개는 주요 영역을 이미 포함하므로 개수는 유지하고 장별 고유 질문 16개를 생성 계약에 추가했다. 장 간 업무/관계 조언 반복을 억제한다.
- 실제 템플릿의 모든 장에 서로 다른 질문이 연결되는 회귀 테스트 통과. 누락된 독립 주제가 확인되면 목차를 확장할 수 있다.
- 후속 집중 테스트 7/7, 최종 타입 검사 및 프로덕션 빌드 통과. 전체 회귀 최종 집계는 tests.md 참조.
- 검증: 전체 회귀 1707/1707 통과(193.3초), 이후 장별 고유 질문 보강 집중 7/7, 타입·프로덕션 빌드 통과. 로컬 합성 모바일 320~430px/데스크톱 표 넘침 0. 운영 실호출/배포 미실행.
