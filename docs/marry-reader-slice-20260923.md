# 결혼궁합 저장 리포트 읽기 화면 — 2026-09-23

## 목적과 범위

- 천명사주의 공용 읽기 위계를 결혼궁합 06 상세에 적용하되 와인·로즈 색상은 유지한다.
- 저장 API의 24개 항목 원문, 계산값, 소유권·결제 권한은 그대로 사용한다. 고객 실데이터를 코드나 기록에 복제하지 않는다.
- 새 후속 요청에 따라 결혼궁합만 24개 목차마다 고유한 실사 컷 한 장씩 사용한다. 다른 여섯 서비스의 대표 이미지 단일화는 유지한다.

## 관측과 결정

- 운영 화면 DOM에는 완료된 항목 24개가 있었지만 `.phone`의 최대 높이와 공용 셸의 `overflow: clip`이 함께 적용돼 뒷부분을 볼 수 없었다. 결혼궁합 상세만 문서 스크롤로 바꾼다.
- 과거 `summary-only` 설정과 JS 선적용 목록 때문에 목차 이미지가 모두 빠졌다. 결혼궁합을 해당 목록에서 제외하고 24개 파일을 섹션 순서로 매핑한다.
- 삽입형 읽기 컴포넌트 일부는 밝은 본문 대신 페이지의 어두운 `--ink`를 사용해 글자가 배경에 묻혔다. 밝은 표면 글자 토큰 `--text`를 사용한다.
- 설정 JSON이 도착하기 전에 구형 저장 컷을 그리지 않도록 결혼궁합 렌더만 설정 로드를 먼저 기다린다. 기다리는 동안 계정이 바뀌면 이전 회원의 결과를 다시 표시하지 않고, 설정 실패 시에는 기존 저장 본문을 계속 표시한다.
- 요약과 첫 하이라이트 이미지는 각기 독립 컷이다. 토글마다 `펼치기 +` / `접기 −`를 표시하고 첫 항목만 기본 펼침을 유지한다.
- 저장 해석이 렌더된 06 상세에서만 중복 상담 입력을 숨긴다. 로딩·오류 상태의 안내/입력은 남기며 공유·PDF 도구는 그대로 둔다.

## 검증 기준

1. 요약·하이라이트·24개 목차의 실사 이미지가 각각 존재하고 중복하지 않는다.
2. 24번째 항목과 하단 공유·PDF까지 스크롤 가능하다.
3. 본문 15px/1.9행간, 한 줄 답·근거·행동·표·그래프·토글 상태를 명확히 읽는다.
4. 저장 본문은 수정·단축·복제하지 않고 다른 서비스 이미지 계약도 바꾸지 않는다.
5. 로컬 단위/타입/서비스 검사와 브라우저 CSS 확인을 분리해 기록한다. 운영 시각 검수는 배포 후 별도 수행한다.

## 재사용 교훈

고정 크기의 폰 미리보기와 공용 sticky 셸을 함께 쓸 때 `overflow: clip`이 긴 리포트의 뒷부분을 접근 불가능하게 만들 수 있다. 이미지 정책을 JSON과 JS의 조기 표시 가드 양쪽에 둔 서비스는 변경 시 두 곳을 함께 갱신해야 한다.

## QA 결과와 남은 확인

- 공용 리더 집중 검증 82/82, 전체 직렬 테스트 1,538/1,538, `check:marry`, TypeScript, Vercel build, 20개 서비스 QA, `git diff --check` 통과.
- 새 WebP 26개는 해시 26개가 모두 다르며 로컬 HTTP HEAD 26/26이 200이다. 총 약 2MB.
- 로컬 브라우저에서 공용 셸 적용 후 결혼궁합 상세의 `max-height: none`, `overflow: visible`을 확인했다. 저장 해석 표시 시의 상담 입력 조건부 숨김은 코드 계약으로 검증했고, 로그인 저장 리포트 시각 검수는 배포 전이다.
- 로그인 회원의 변경 후 실제 운영 화면 시각 검수, 원격 배포는 아직 수행하지 않았다. 로컬 정적 서버는 회원 API를 제공하지 않으므로 저장 본문을 합성 데이터로 위장해 완료 판정하지 않았다.
