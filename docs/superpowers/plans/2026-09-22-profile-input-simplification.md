# 프로필 입력 간소화 — 로컬 구현 계획

## 요구와 결과

- 대상: `/profile`의 사주 기본정보 수정 화면과 저장 해석의 공통 현실 기준 안내.
- 사용자 과업: 이름·출생정보만 쉽게 저장하고 해석을 읽는다. 다섯 가지 현실 조건을 프로필에서 미리 작성할 필요가 없다.
- 성공 기준: 선택 현실 조건 필드 0개, 출생 시각 선택과 저장 버튼의 명확한 간격, 시간 모름 선택 시 입력 숨김 및 접근성 상태 전달, 기존 회원 맥락 데이터 보존.

## 결정

1. 프로필의 현실 조건 입력 다섯 칸을 제거한다. 별도 자유질문 칸도 만들지 않는다. 질문은 서비스 맥락이 있을 때 묻는 것이 적절하다.
2. 프로필 PUT에서 `lifeContext`를 생략한다. 서버의 기존 값 보존 계약을 그대로 쓴다. DB 구조와 저장된 원문은 바꾸지 않는다.
3. 저장 해석에 회원 현실 조건이 없다면 프로필 등록을 독촉하지 않는다. 만세력 계산 기반 흐름은 표시하고, 직장·보상·관계의 실제 사실은 확인 질문으로 구분한다.
4. 기존 검정·금색 브랜드와 공통 상단/하단을 유지한다. 시간 토글과 시각 입력은 독립된 간격과 44px 이상 버튼으로 구성한다.

## 검증

- 정적 HTML/JS/CSS 계약과 빈 회원 맥락 렌더링 회귀 검사.
- 기존 회원 맥락 보존 단위 검사.
- TypeScript·전체 테스트·Vercel 빌드·diff 검사.
- 운영 배포, DB 변경, 팝업 관리자/팝업 변경은 범위 밖.
