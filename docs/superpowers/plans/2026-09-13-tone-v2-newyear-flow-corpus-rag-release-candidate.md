# newyear_flow corpus/RAG release candidate plan

Task: `task-tone-v2-p05-newyear-flow-corpus-rag-release-candidate`

## Objective

Preserve the current 2.0.0 annual-flow corpus for stored reports, create an explicitly reviewed 2.1.0 candidate for new snapshots, and prove retrieval, prompt and saved-prose review isolation.

## Scope

1. Freeze the original ten block IDs, source file and hash.
2. Add a failing executable contract for registry activation, ten semantic reviews, evidence boundaries, active/stored retrieval, hash mismatch, prompt pinning, saved-prose review and truthful release state.
3. Build ten unique blocks separating user input, server-calculated year/season/ten-year-cycle values, symbolic interpretation, unknown future reality and labeled hypothetical examples.
4. Remove invented work, money, relationship, health and routine claims; remove unsupported period, count and outcome prescriptions.
5. Activate 2.1.0 only for new snapshots, preserve 2.0.0 rollback and bind local evaluation/release evidence.
6. Run focused, related and full regression, typecheck, Vercel build, deterministic replay, review, credential boundary and ProjectOps closure.

## Non-scope

- Provider generation or provider-output quality claims.
- Production deployment, customer-record mutation, database/auth/payment/admin changes.
- Commit, push or deployment.

## Acceptance

- 10/10 review entries pass and examples are explicitly hypothetical.
- Calendar year, solar-term year, annual cycle and ten-year cycle values come only from server calculations.
- No certain event, relationship, financial, medical, legal, career or personal-state inference.
- No arbitrary period, count, date or schedule prescription.
- Old snapshots remain retrievable and fail closed on hash mismatch.
- Candidate, review and release artifacts are deterministic, reversible and truthful.
