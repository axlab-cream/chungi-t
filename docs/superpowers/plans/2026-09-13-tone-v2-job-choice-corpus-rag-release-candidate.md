# job_choice corpus/RAG release candidate plan

Task: `task-tone-v2-p05-job-choice-corpus-rag-release-candidate`

## Objective

Preserve the current 2.0.0 job-choice corpus for stored reports, create an explicitly reviewed 2.1.0 candidate for new snapshots, and prove retrieval, prompt and saved-prose review isolation.

## Scope

1. Freeze the original 12 block IDs, source file and hash.
2. Add a failing executable contract for registry activation, semantic reviews, evidence boundaries, active/stored retrieval, hash mismatch, prompt pinning, saved-prose review and truthful release state.
3. Separate user-confirmed offer facts and documents, server calculations, symbolic questions, unknown employer reality and labeled hypothetical examples.
4. Remove invented role, organization, compensation, commute, contact, health and negotiation facts plus unsupported periods/counts.
5. Keep Ziwei palace names as uncalculated viewpoints unless an actual chart calculation exists.
6. Activate 2.1.0 only for new snapshots, preserve 2.0.0 rollback and run focused, related, full, build, deterministic, review and ProjectOps gates.

## Non-scope

- Provider generation or provider-output quality claims.
- Production deployment, customer-record mutation, database/auth/payment/admin changes.
- Commit, push or deployment.

## Acceptance

- 12/12 review entries pass and examples are explicitly hypothetical.
- Offer/employment reality comes only from user input or verified documents.
- No employer intent, role, culture, pay, career outcome, health, legal or personal-state inference.
- No arbitrary period, count, date or schedule prescription.
- Old snapshots remain retrievable and fail closed on hash mismatch.
- Candidate, review and release artifacts are deterministic, reversible and truthful.
