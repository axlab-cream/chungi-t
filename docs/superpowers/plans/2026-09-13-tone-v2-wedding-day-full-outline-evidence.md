## Goal

Make the supplied three-part, 20-item `wedding_day` outline an immutable executable contract and retain one fresh isolated synthetic provider run with production-equivalent replay evidence.

## Vertical slice

1. Freeze only source hashes, group headings and item headings; do not ingest sample prose.
2. Align the runtime TOC and prove a new stored report owns 20 immutable pending section identities.
3. Generate in strict order in ignored local file storage, stopping at the first unresolved failure.
4. Replay accepted prose through the same grounding, persona, tone, duplication, privacy, safety, professional-boundary and continuity review path.
5. Store only hashes, model/usage metrics and review outcomes in tracked evidence.
6. Attach that evidence to the existing reversible 2.1.0 candidate and regenerate the aggregate truthfully.

## Boundaries

- Synthetic inputs only.
- No source example prose in runtime, corpus or evidence.
- No credentials, partner birth data, raw provider prose or customer identifiers in tracked files.
- No Production, customer record, Supabase, deployment, commit or push changes.
