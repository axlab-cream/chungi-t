# 운영 관리자 개편 — IA 확정안과 단계별 계획

작성 2026-10-06 · 대상 `admin-ui/index.html`, `/api/admin/v1/*` · 브랜치 `claude/admin-edits`

## 0. 개편 기준

1. **사이드바 = 업무 영역.** 세부 기능(주문·환불·정산 등)은 화면 안의 탭과 상세로 넣는다.
2. **메뉴에 들어가면 목록·현황이 먼저.** 작성 화면은 `＋ 새 …` 버튼 뒤로 보낸다.
3. **목록 → 상세 → 처리 → 결과 확인이 한 흐름.** 등록·실행한 뒤 운영자가 결과를 어디서 보고, 문제를 어디서 발견하고, 어디서 처리하는지 화면 안에 있어야 한다.
4. **운영자 말로 쓴다.** 개발 용어(canonicalKey, 경로, 해시, 원문 ID, 오류 코드)는 기본 화면에서 뺀다. 꼭 필요한 설명은 ⓘ 툴팁에 넣는다. ID는 복사 버튼이 달린 짧은 표기로만 보인다.

## 5. API 정리

### 5-1. 원칙
- 업무 영역별 경로: 목록 `GET /api/admin/v1/{영역}`, 상세 `GET …/{id}`, 처리 `POST …/{id}/{동작}`.
- 목록은 모두 `limit`·`cursor`(또는 `offset`)·기간·상태 필터를 받는다.
- 화면용 응답은 **운영자 말로 된 표시값**을 함께 준다(예: `status: 'partial'` + `statusLabel: '일부 실패'`). 원문 ID·코드는 상세 모달의 ⓘ·복사 버튼용으로만 둔다.
- 옛 경로는 새 화면이 다 옮겨질 때까지 그대로 둔다(동시 운영 후 정리).

### 5-2. 바로 고칠 것 (보안·정합성)
| 문제 | 조치 |
|---|---|
| `GET /orders`가 로그인 없이 공개(회원 ID·리포트 ID·금액 노출) | `orders:read` 필수로 바꾸고 공개 캐시 제거. 공개 주문 화면 모드 제거 |
| `POST /reports/requeue-incomplete`가 읽기 권한으로 쓰기, 감사 없음 | `reports:write` + 감사 기록 |
| 쿠폰 발급·중단이 감사 기록에 안 남음 | 감사 기록 추가 |
| 리포트 목록 상태가 항상 "new"(`admin_status`) | 실제 생성 상태(`payload.status`)로 바꾼다 |

### 5-3. 새로 만들 API
| API | 쓰는 화면 | 데이터 |
|---|---|---|
| `GET /dashboard` | 대시보드 | 오늘·어제 같은 시각까지: 신규 회원, 결제 회원, 결제액, 환불 요청, 리포트 생성, 문의 + 처리 필요 4종 |
| `GET /search?q=` | 상단 통합 검색 | 이름·이메일 일부, 주문번호, 리포트 ID, 회원 ID를 한 번에 |
| `GET /payments` (+필터) / `GET /payments/:id` | 결제 관리 | 주문 + 결제 시각(재무 기록) + 결제 경로(웹·앱) + 리포트 + 환불 |
| `POST /refunds/:id/reject` | 환불 탭 | 반려(상태 `rejected`) |
| `GET /payments/revenue?by=day\|month\|service\|method` | 매출 탭 | 결제액·환불액·실결제액. 수수료는 데이터가 없어 P2 |
| `GET /members?q&paid&from&to` / `GET /members/:id/overview` | 회원 관리 | 목록 필터 + 상세 탭(결제·리포트·문의·쿠폰·푸시 기기) 한 번에 |
| `GET /reports?status&service&cursor` / `GET /reports/:id` | 리포트 관리 | 실제 상태, 입력 요약, 모델, 실패 항목, 생성 시간(시도 기록에서 계산) |
| `GET /ai/failures?period` | AI 운영 › 실패 현황 | 실패 수·실패율·오류 유형별 |
| `GET /messages` / `GET /messages/:id` | 메시지 | 푸시 + 카카오 통합 발송 내역 |
| `POST /push/:id/resend-failed` | 메시지 상세 | 실패 기기만 새 발송으로 |
| `GET /consultation/usage` | 상담 관리 | 회원별 상담 장부에서 이용·결제·무료 사용 집계 |
| `GET /support?status&q` / `GET /support/:id` | 고객 지원 | 상태 필터 + 상세에 회원·주문·리포트 요약 |
| `GET /audit?actor&action&from&cursor` | 시스템 › 로그 | 필터·페이지 넘김 |

### 5-4. 데이터가 없어 지금은 못 하는 것 (P2·결정 필요)
- 회원 전화번호, 마케팅 동의, 푸시 동의, 탈퇴 상태(지금은 정지만).
- 결제 수수료·순매출(설정값으로 수수료율을 둘지 결정), PG 실제 환불 실행.
- 문의 본문·제목(문의 접수 경로가 없다 — 고객 문의 채널부터 정해야 한다).
- 할인·상담 쿠폰 실제 사용 집계, 감사 기록의 사유·변경 전후 값.
- 관리자 역할 나누기(CS·마케팅·콘텐츠·개발).
