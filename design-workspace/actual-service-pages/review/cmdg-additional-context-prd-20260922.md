# 천명사주 검토본 — 추가 정보 입력 패턴

상태: 로컬 격리 검토본 구현 완료 · 운영 반영 전  
대상: `review/cmdg-longform.html`

## 문제와 목표

저장 리포트에는 사주 계산과 생성 당시의 해석만 있고, 현재 직장의 역할·평가·보상·소진이나 새 제안의 조건처럼 현실 판단에 필요한 사실이 없다. 이 빈칸을 예언으로 채우지 않고, 독자가 확인한 실제 조건을 적어 해당 카드의 확인표에 반영한다.

## 사용자 결과

1. **일·이직 비교** — 현재 자리와 새 선택의 역할·평가·보상·소진을 각각 한 문장으로 비교한다.
2. **제안·보상 확인** — 맡을 일·보상·마감의 실제 조건을 한 문장으로 기록한다.
3. **관계의 실제 조건** — 실제 약속·부담·다음 조정 범위를 한 문장으로 기록한다.
4. **현재 계획** — 현재 책임·올해 제안·결정 전 질문을 한 문장으로 기록하고, 전통 해석의 기간 표기와 구분한다.

## 동작 계약

- 카드에서 `추가 정보 입력`을 누르면 해당 맥락의 입력칸이 열린다.
- 한 항목 이상을 적고 `입력 내용 반영`을 누르면, 같은 맥락을 쓰는 다른 카드와 비교표에 동기화한다.
- 비어 있는 항목은 `직접 확인`으로 남긴다. 입력 내용으로 유지·이직·관계 결과·수입·시기를 자동 판정하지 않는다.
- `입력한 내용 지우기`는 그 맥락의 모든 입력칸과 연결된 비교표를 현재 페이지 안에서 초기 상태로 되돌린다.
- 모든 사용자 입력은 공백을 정리한 뒤 최대 120자로 표시하며, DOM에는 `textContent`로만 출력한다.

## 개인정보·범위

- 현재 구현은 브라우저 메모리 안에서만 동작한다. API 호출, 리포트 저장, 계정 프로필 반영, `localStorage`·`sessionStorage`·URL 파라미터 사용이 없다.
- 따라서 새로고침·탭 닫기 후 값은 남지 않는다.
- 운영 반영 시에는 별도의 동의 문구, 저장 위치·보존 기간, 접근 권한, 수정·삭제 정책과 서버 검증을 설계해야 한다. 이 검토본의 값을 운영 데이터로 취급하지 않는다.

## 검증 기준

- 초기 직장 비교표는 현재 자리·새 선택 두 셀 모두 `직접 확인`을 표시한다.
- 현재 자리와 새 선택의 두 문장을 입력하면 두 셀이 입력값으로 바뀌고, 안내 문구는 “입력한 실제 조건”만 반영했음을 말한다.
- 제안·관계·계획은 각 한 문장만 입력하며, 초기화하면 모든 셀과 안내 문구가 초기 상태로 돌아간다.
- 제안·관계·계획 카드에 같은 추가 정보 UI 패턴이 제공된다.
- 기존 16개 원문, 사진, 공통 GNB·하단 메뉴, 운영 파일은 바꾸지 않는다.
