# PDF 페이지 정책

## 현재 구현 결론

**현재 20개 서비스에는 고정 PDF 페이지 수 계약이 없다.**

공용 리포트는 HTML을 새 창에 만들고 브라우저의 `인쇄 → PDF로 저장`을 호출한다. 전문 서비스 일부도 같은 방식 또는 현재 화면의 `window.print()`를 사용한다. 따라서 다음 조건에 따라 장수가 달라진다.

- LLM이 생성한 실제 글자 수와 단락 수.
- 이미지·차트·표의 높이.
- 브라우저와 운영체제의 폰트 대체.
- 인쇄 배율, 여백, 용지, 머리글·바닥글 설정.
- `break-inside: avoid`가 긴 항목을 다음 장으로 미는 정도.

현재 소스에는 PDF 생성 뒤 총 페이지를 계산하거나, 목표 장수를 넘으면 다시 편집하는 로직이 없다. 따라서 `해석 장 37개`를 `PDF 37장`이라고 부르면 안 된다.

## 확인된 PDF 방식

| 영역 | 현재 방식 | 고정 장수 |
|---|---|---|
| 천명사주 공용 리포트 | 표지 + 기본 정보 + 목차 + 전체 섹션을 새 인쇄창에서 출력 | 없음 |
| 전문 서비스 공용 PDF | 저장된 전체 섹션을 단순 A4 HTML로 조립해 출력 | 없음 |
| 올해 연애운·고양이 궁합 일부 화면 | 현재 화면 `window.print()` | 없음 |
| 오늘운 | 전용 PDF 장수 계약 없음 | 없음 |

근거: `사주/js/chat.js`, `사주/js/umsh-report-pdf.js`, 각 상세 화면의 PDF 버튼 코드.

## 목표 장수 확정 뒤 필요한 코드 계약

1. 서비스별 `pdfTargetPages`와 `pdfChapterPlan`을 단일 설정에 둔다.
2. 화면용 장문과 PDF용 편집 본문을 같은 문자열로 억지 공유하지 않는다.
3. 표지, 요약, 목차, 챕터, 실행표의 페이지 예산을 먼저 배정한다.
4. Playwright 또는 브라우저 PDF 생성으로 실제 페이지 수를 측정한다.
5. 목표 장수보다 길면 글자를 잘라내지 않고 중복 문단을 통합하거나 PDF 요약을 다시 생성한다.
6. 목표보다 짧으면 일반론을 늘리지 않고 사례, 비교표, 계산 근거의 쉬운 설명을 보강한다.
7. 모바일 화면 QA와 A4 PDF QA를 별도 승인한다.

## 집 풍수 12장 권장 구성

사용자가 별도로 요청한 `12장` 요구를 가장 직접적으로 반영할 수 있는 구성이다.

| 페이지 | 내용 |
|---:|---|
| 1 | 이 집과 나의 전체 적합도·핵심 점수·한 줄 결론 |
| 2 | 터 유사도와 지형 흐름 |
| 3 | 바깥 물길·도로·바람 |
| 4 | 빛·공기·소음 |
| 5 | 건물·세대 기본 체력 |
| 6 | 현관·귀가 동선 |
| 7 | 수면·회복 |
| 8 | 재택·공부·집중 |
| 9 | 돈·살림·소비 동선 |
| 10 | 관계·가족·동거 |
| 11 | 내 사주·연간 기운과 집 오행 핏 |
| 12 | 유지·손질·후보지 비교와 7일·30일 액션 |

각 장은 자기 제목에만 답한다. 침실·창·책상·현관 전체 순회는 1페이지에서만 허용한다.
