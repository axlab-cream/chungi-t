# UMSH 커플궁합 단일 서비스 구축

## 목표

- 서비스: 커플궁합
- 질문: 우리 둘, 진짜 잘 맞아?
- 분류: 관계 > 커플궁합
- URL: `/match/couple`
- 가격: 19,900원
- 분석 기준: 명리궁합, 오행, 일지, 합충, 갈등 후 회복 방식

## 재사용한 아키텍처

- 인증: 기존 Supabase OAuth 세션과 `requireSupabaseUser` 재사용
- 사용자 사주: 기존 기본 사주 프로필 조회 및 불완전 프로필 등록 흐름 재사용
- 상대 사주: 생년월일 8자리, 성별, 양력/음력 입력 후 기존 `analyzeSaju`로 별도 분석
- RAG: 기존 `retrieveRagChunks`를 사용하고 커플궁합·오행·일지·합충·갈등·회복 키워드로 검색
- 저장: 기존 `saveReportRecord`와 소유자 ID 기반 보고서 저장 방식 재사용
- UI: 기존 단일 서비스의 로그인 → 프로필 → 상대 입력 → 대분류 → 중분류 → 상세 풀이 구조 재사용

## 목차 구조

1. 처음엔 잘 맞는데, 왜 자꾸 엇갈리는가
2. 사랑의 속도가 다른 데는 이유가 있습니다
3. 일지는 숨겨 둔 연애 습관을 보여줍니다
4. 오래 가는 커플은 싸우는 법이 다릅니다
5. 우리 둘, 계속 가도 되는 관계인가

총 5개 대분류, 21개 중분류를 생성한다. 궁합을 확정 점수로 단정하지 않고 두 사람의 확인 가능한 행동, 갈등 조건, 회복 규칙으로 연결한다.

## API와 보안

- `POST /api/match/couple/analyze`
- 비로그인 요청은 기존 인증 미들웨어에서 401로 차단한다.
- 새 테이블, 새 RLS 정책, 새 운영 환경 변수는 추가하지 않는다.
- 동일 사용자·사주·상대 입력은 결정적 report ID를 생성해 중복 보고서를 줄인다.

## 검증 기준

- 타입 검사와 전체 단위 테스트 통과
- 비로그인 API 401 확인
- 홈 대표 궁합 배너에서 `/match/couple` 이동 확인
- 운영 페이지에서 로그인 게이트, 콘솔 오류, 자산 로딩 확인
