## Improvement / 재발 방지 규칙

```powershell
npm run check:production-source -- --expected-head=<배포할 전체 커밋 SHA>
```

- 배포 전 원격 main을 갱신하고, 작업 트리가 깨끗하며 최신 main을 포함하는지 검사한다. 승격 직전에도 같은 HEAD로 검사한다. 관련 10개 테스트 통과.
- 이 명령은 수동 사전 검사다. 다른 PC가 이를 생략하고 CLI 배포하는 것을 자동 차단하지 않는다. ignored 파일, 실제 아티팩트 커밋, 동시 배포 여부는 별도 확인해야 한다.
- 통합 소스를 원격 main에도 fast-forward로 반영해야 한다. 다른 PC는 최신 main을 받은 뒤 작업·배포해야 한다. 강제 푸시나 기존 작업 리셋은 사용하지 않는다.

## Theory / REG 재사용

- 호스팅의 현재 Production alias와 Git main은 별개의 상태다. READY 배포 기록·생성 시각·소스 SHA를 대조하고, 웹 파일의 일치만으로 빌드 실패나 강제 푸시를 단정하지 않는다.
- 통합은 최신 소스뿐 아니라 이미 운영 중인 미커밋 변경의 보존 여부까지 확인해야 한다. 저장된 고객 해석은 소스 통합을 이유로 재생성하거나 덮어쓰지 않는다.
- 후보 배포는 `--prod --skip-domain`으로 생성하고 READY·health·정적 파일·소스를 확인한 후 승격한다.
- 함수 에셋 범위 최적화는 별도 과제다. 원본 폴더 크기만으로 실제 배포 실패를 단정하지 않으며 이번 통합에서 대규모 자산 이동은 하지 않는다.
